# Commit Rules

## 📌 Allgemeine Regeln

**Jeder Commit MUSS** den [Conventional Commits](https://www.conventionalcommits.org/) Standard einhalten.

---

## ✅ Richtige Commit-Messages

### Format
```
<typ>(<scope>): <Beschreibung>

[Leere Zeile]
[Optional: detaillierte Änderungen als Aufzählung]
```

### Beispiele
| Typ | Scope | Beschreibung | Vollständige Message |
|-----|-------|--------------|---------------------|
| `feat` | `ci` | GitHub Actions Workflow hinzufügen | `feat(ci): add GitHub Actions workflow for GHCR` |
| `fix` | `docker` | Cache-Konfiguration entfernen | `fix(docker): remove cache config causing buildx errors` |
| `docs` | – | Readme aktualisieren | `docs: update README with deployment instructions` |
| `chore` | `deps` | Abhängigkeiten aktualisieren | `chore(deps): update dotnet to v10.0` |
| `refactor` | `imap` | Code umstrukturieren | `refactor(imap): extract ReconnectCircuitBreaker class` |

---

## ❌ Verboten

| ❌ Schlechte Message | ✅ Korrekte Alternative |
|------------------------|-------------------------------|
| `Add` | `feat(ci): add GitHub Actions workflow` |
| `Fix` | `fix(docker): remove cache backend config` |
| `Update` | `chore(deps): update docker-compose files` |
| `WIP` | `feat(ui): add progress bar fixes` |
| `fix typo` | `fix(docs): correct typo in README` |
| `oops` | `fix(ci): correct workflow syntax error` |

---

## 📝 Typen & Scopes

### Typen
| Typ | Verwendung |
|-----|------------|
| `feat` | Neue Features |
| `fix` | Bugfixes |
| `docs` | Dokumentationsänderungen |
| `style` | Formatierungen (keine logischen Änderungen) |
| `refactor` | Code-Umstrukturierungen |
| `perf` | Performance-Optimierungen |
| `test` | Tests hinzufügen/korrigieren |
| `chore` | Wartungsaufgaben (Build, Abhängigkeiten, etc.) |
| `revert` | Commits rückgängig machen |

### Häufige Scopes in diesem Projekt
| Scope | Bereich |
|-------|---------|
| `ci` | Continuous Integration (GitHub Actions, Workflows) |
| `docker` | Docker-Dateien (Dockerfile, docker-compose) |
| `deps` | Abhängigkeiten |
| `imap` | IMAP-Funktionalität |
| `ui` | Benutzeroberfläche |
| `db` | Datenbank |
| `api` | API/REST-Endpunkte |
| `test` | Tests |
| `docs` | Dokumentation |

## 🔧 Tools

### Commit-Message prüfen
```bash
# Install commitlint (Node.js erforderlich)
npm install -g @commitlint/cli @commitlint/config-conventional

# Prüfe deine Message
echo "feat(ci): add workflow" | commitlint
```

### Git Hook für automatische Prüfung
Erstelle `.git/hooks/commit-msg`:
```bash
#!/bin/sh
commitlint -E HUSKY_GIT_PARAMS
```

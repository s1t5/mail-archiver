# Mailcow インスタンスのアーカイブ {#mailcow-instance-archiving}

[← ドキュメントインデックスに戻る](index.md)

## 概要 {#overview}

Mail Archiver は、メールボックスの所有者の個人パスワードを収集することなく、[Mailcow](https://mailcow.email) インスタンスのメールボックスを中央集中型でアーカイブできます。

管理者は、API キーを使用してインスタンスに一度だけ接続します。その後、Mail Archiver はメールボックスをリストアップし、アーカイブ用に選択された各メールボックスに対して、`imap_access` に限定された**専用のアプリパスワード**を作成します。このアプリパスワードは、既存の IMAP プロバイダーによってメールボックスをアーカイブするために使用され、いつでも失効させることができます。

管理者は、**Add Account → Mailcow**、またはすでに Mailcow によって管理されているアカウントのアクションメニューからインスタンスマネージャーにアクセスできます。保存された API キーによってインスタンス内のすべてのメールボックスの資格情報を管理できるため、マネージャーは管理者専用です。

## Mailcow からのアカウント作成 {#creating-accounts-from-mailcow}

**Mail Accounts → Add Account** で、管理者はプロバイダーとして **Mailcow** を選択できます。すると、フォームに接続済みのインスタンスと **Manage mailboxes** アクションが表示されます。そこでメールボックスを選択すると、専用のアプリパスワードを持つ通常の IMAP アーカイブアカウントが作成されます。個別の Mailcow アカウントは保存されません。まだインスタンスが存在しない場合は、**Manage Mailcow instances** を開いてインスタンスマネージャーから接続できます。

## 既存のアカウントの紐付け {#linking-an-existing-account}

IMAP アカウントの編集ビューで、管理者はプロバイダーを **Mailcow** に切り替えてインスタンスを選択できます。アカウントは IMAP プロバイダーを維持したまま Mailcow 管理下に取り込まれます。Mail Archiver は専用のアプリパスワードを作成して IMAP 経由で検証し、アカウントに保存されているパスワードを置き換えます。その後、アカウントリストに Mailcow アクションが付いた状態でアカウントが表示されます。

Mailcow 管理を解除するには、別のプロバイダーを選択して保存します。アプリパスワードは失効し、ローカルのパスワードはクリアされます。IMAP に戻す場合は、新しい IMAP パスワードを入力してください。Microsoft 365 またはインポート専用アカウントに切り替える場合は、それぞれの資格情報が提供されます。非管理者は、Mailcow 管理下のアカウントの資格情報以外の設定を編集することはできますが、紐付けや解除を行うことはできません。

## 前提条件 {#prerequisites}

### 資格情報の暗号化が有効であること {#credential-encryption-must-be-enabled}

Mail Archiver は、既存の資格情報暗号化機能を使用して、Mailcow API キーと生成されたすべてのアプリパスワードを保存時に暗号化して保存します。インスタンスに接続する前に、以下を設定してください。

```
Security__CredentialEncryptionKey=<base64-encoded 32-byte key>
```


暗号化が無効な間は、インスタンスの作成もメールボックスの有効化も拒否されるため、この機能を通じて資格情報がプレーンテキストとして書き込まれることはありません。キーはデータベースの外に保管し、安全なバックアップに含めてください。キーがないと、保存されたアプリパスワードを復号できず、メールボックスをプロビジョニングできません。詳細は [Setup](Setup.md#-security-settings) を参照してください。

### Mailcow API へのアクセス {#mailcow-api-access}

Mailcow の **Configuration → Access → API** で API キーを作成します。このキーには以下の権限が必要です。

- メールボックスのリスト表示 (`get/mailbox/all`)
- アプリパスワードのリスト表示、作成、削除 (`get/app-passwd/all`, `add/app-passwd`, `delete/app-passwd`)

Mailcow の API 設定で、API のアクセスを Mail Archiver ホストの IP アドレスに制限してください。Mailcow の app-password エンドポイントを使用するには、インスタンスで **App Passwords** 機能が有効になっている必要があります。

### ネットワークアクセス {#network-access}

- Mailcow のオリジンへの **HTTPS** (例: `https://mail.example.com`)。
- IMAP ホストへの **IMAP over TLS** (通常はポート `993`)。プロビジョニングにおいてプレーンテキストの IMAP はサポートされていません。

## 使用手順 {#step-by-step-usage}

### インスタンスへの接続 {#connecting-an-instance}

1. 管理者として Mail Archiver にサインインします。
2. **Mail Accounts** を開き、**Mailcow instances** をクリックします。
3. **Connect Mailcow instance** をクリックします。
4. 接続の詳細を入力します：
   - **Account name** — Mail Archiver 上でのインスタンスの表示名。
   - **Mailcow URL** — HTTPS オリジンのみ（例: `https://mail.example.com`）。パス、クエリ文字列、埋め込まれた資格情報は拒否されます。
   - **API key** — Mailcow で作成したキー。
   - **IMAP host** — アーカイブに使用するホスト名（例: `mail.example.com`）。スキームやポートを含めず、ホスト名のみを入力してください。
   - **IMAP TLS port** — デフォルトは `993` です。
5. **Connect** をクリックします。Mail Archiver はインスタンスを保存する前に、メールボックスをリストアップして API キーを検証します。成功すると、メールボックスの選択画面が開きます。

API キーは暗号化されて保存され、フォームやエラーメッセージに表示されることはありません。API コールに対して HTTP リダイレクトは無効化されているため、キーが別のオリジンに転送されることはありません。

### メールボックスの有効化 {#activating-mailboxes}

1. メールボックスページで、必要に応じて検索フィールドを使用してリストをフィルタリングします。フィルタはアドレスと表示名に一致し、大文字小文字を区別しません。
2. アーカイブするメールボックスを選択します。**Select all** と **Clear selection** は現在表示されている（フィルタリングされた）メールボックスにのみ影響するため、フィルタリングはサブセットを選択する安全な方法です。
3. **Activate archiving** をクリックします。

選択された各メールボックスに対して、Mail Archiver は以下の処理を行います：

1. Mailcow の現在のメールボックスリストと照合してアドレスを再検証し、無効化されているメールボックスは無視します。
2. `{instance name} – {mailbox display name}` という名前のアーカイブアカウントを作成します。
3. `imap_access` に限定された、`MailArchiver-<unique id>` という名前のランダムなアプリパスワードを生成します。
4. TLS 経由の IMAP ログインで資格情報を検証します。
5. 検証が成功した後にのみ、同期を有効にします。

IMAP 検証に失敗した場合、アカウントは無効なままとなり、再試行が可能です。

### メールボックスのステータスバッジ {#mailbox-status-badges}

選択ページでは、チェックボックスが利用可能かどうかの理由を明確にするために、各メールボックスにラベルが付いています。

| バッジ | 意味 | 選択可能 |
| --- | --- | --- |
| **Available** | Mailcow にリストされているが、まだプロビジョニングされていない | yes |
| **Active** | プロビジョニング済みで同期中 | no |
| **Pending** | プロビジョニングが開始されたが完了していない（再試行可能） | yes |
| **Revoked** | アプリパスワードが失効した。再度有効化可能 | yes |
| **Existing** | このアドレスを持つ独立した IMAP アカウントが既に存在する | no |
| **Disabled** | メールボックスが Mailcow で無効化されている | no |

### 保留中のメールボックスの再試行 {#retrying-a-pending-mailbox}

生成された資格情報と一意のアプリパスワード名は、Mailcow API が呼び出される**前**に永続化されます。リクエストが曖昧に失敗した場合（例：アプリパスワード作成後のタイムアウトなど）、メールボックスは **Pending** として表示され続けます。ページをリロードして再度選択してください。Mail Archiver はまずアプリ名を検索し、存在しない場合にのみ新しいアプリパスワードを作成します。再試行によって重複した資格情報が蓄積されることはありません。

1つのインスタンスのプロビジョニングと失効は PostgreSQL のアドバイザリロックを使用してシリアル化されるため、2つの同時実行操作によって同じメールボックスが二重にプロビジョニングされることはありません。

### アクセスの失効 {#revoking-access}

メールボックスの横にある **Revoke app password** をクリックします。これにより、以下の処理が行われます：

- 今後の同期を無効にする
- Mailcow 内の管理対象アプリパスワードを削除する
- ローカルのパスワードをクリアする

**アーカイブされたメールは保持されます。** 管理対象のアプリパスワードのみが削除され、そのメールボックスに属する他のアプリパスワードには一切影響しません。実行中の同期操作は、既存の接続で終了する場合があります。

リモートリクエストが失敗した場合、アカウントは無効なままとなり、失効の再試行が可能です。

**Mail Accounts** でアーカイブアカウントを削除しても、リモートの資格情報はサイレントに削除されません。紐付けはインスタンスページの **Remaining app passwords** にリストされたままとなり、明示的に失効させることができます。

### インスタンスの編集 {#editing-an-instance}

**Mailcow instances** を開き、**Edit** をクリックします。API キーフィールドは常に空です。保存されたキーが表示されることはありません。現在のキーを維持する場合は空のままにし、置き換える場合は新しいキーを入力してください。変更された接続詳細は、保存前に Mailcow に対して検証されます。

### インスタンスの削除 {#deleting-an-instance}

**Mailcow instances** を開き、**Delete** をクリックします。

インスタンスを削除すると、暗号化された API キーとメールボックスの紐付けが削除されます。**アーカイブアカウントとそのアーカイブされたメールは保持されます**が、アカウントは無効になります。

Mailcow 内で**管理対象のアプリパスワードがまだアクティブな場合、削除は拒否されます**。インスタンスを削除すると、それを失効させるために必要な API キーも削除されてしまうためです。先にメールボックスページですべての管理対象アプリパスワードを失効させてください。

## 監査ログ {#audit-logging}

すべての管理操作は、実行したユーザーとともにアクセスログに記録されます：

- インスタンスの接続
- インスタンスの更新
- インスタンスの削除
- メールボックスの有効化（プロビジョニングされた数と失敗した数を含む）
- アプリパスワードの失効

## メールボックスの制限 {#mailbox-limit}

1回の有効化実行でプロビジョニングできるメールボックスは、最大で `Mailcow__MaxSelectedMailboxes` 個（デフォルト `1000`）です。これは、誤った大量のプロビジョニングや、Mailcow API および IMAP への過剰な負荷を防ぐためのものです。大規模なインスタンスの場合は、操作を数回に分けて実行してください。

各メールボックスには、複数の API ラウンドトリップと IMAP 検証が必要であり、これらは順次処理されます。一度のリクエストで数百のメールボックスをプロビジョニングしようとすると、リバースプロキシやブラウザのタイムアウトを超える可能性があるため、選択をバッチに分割してください。

## セキュリティに関する注意 {#security-notes}

- API キーはサーバー側に保持されます。キーは `X-API-Key` ヘッダーとして送信され、ログからは伏せられ、ブラウザに返されることはありません。
- Mailcow の app-password レスポンスは、その `log` フィールドにプレーンテキストのパスワードをエコーバックする可能性があります。Mail Archiver は意図的にレスポンスボディをログに記録せず、API エラーをブラウザに表示しません。失敗はローカライズされたメッセージとして報告されます。
- HTTP 200 レスポンスは成功として扱われません。変更操作には Mailcow の結果ごとの `type: success` が必要です。
- IMAP の権限は本質的に読み取り専用ではありません。プロビジョニングされたアカウントにはサーバー側の削除ポリシーは設定されておらず、管理者はアカウント設定の制御権を保持します。この機能はメッセージをアーカイブするものであり、Mailcow の設定やバックアップをアーカイブするものではありません。

### ホスト名とプライベートネットワーク {#hostnames-and-private-networks}

Mailcow URL と IMAP ホストは管理者によって入力され、プライベートアドレス空間を指す場合があります。これは意図的なものであり、サポートされています。Mail Archiver は通常メールサーバーの隣にデプロイされるため、`mail.example.lan`、`192.168.10.20`、または `10.0.0.5` は一般的な値です。**プライベート、ループバック、またはリンクローカルアドレスがブロックされることはありません。**

信頼の境界はネットワークアドレスではなく、管理者ロールにあります。セルフマネージャーには `Mail Accounts` が利用可能であり、すでに自身のカウント用に任意の IMAP サーバーを構成している場合があります。Mailcow セクションは管理者に限定されており、管理者はすでにインストール内のすべてのアーカイブアカウントに対して無制限のアクセス権を持っています。したがって、IMAP ホストを制限しても権限の境界を閉じることにはならず、意図されたオンプレミス展開を損なうだけになります。

ただし、以下の2つの制約は依然として適用されます：

- Mailcow URL は純粋な HTTPS オリジンである必要があります。パス、クエリ文字列、ユーザー情報、リダイレクトは拒否されるため、API キーが別のオリジンに転送されることはありません。
- IMAP ホストはスキームやポートを含まないホスト名である必要があり、プロビジョニングは常に TLS (`SslOnConnect`) を使用して接続します。

Mail Archiver が到達できるホストを制限する必要がある場合は、アプリケーション内の入力バリデーションに頼るのではなく、ネットワーク層（エグレスファイアウォールルールやコンテナの DNS ポリシーなど）で強制してください。

## トラブルシューティング {#troubleshooting}

| 症状 | 原因と対策 |
| --- | --- |
| 接続時または有効化時に *Encryption required* と表示される | `Security__CredentialEncryptionKey` が設定されていないか、無効です。base64 エンコードされた 32 バイトのキーを設定して再起動してください。 |
| *HTTPS origin required* と表示される | URL にパス、クエリ文字列、または埋め込まれた資格情報が含まれています。例: `https://mail.example.com` のようなプレーンなオリジンを入力してください。 |
| *IMAP host invalid* と表示される | IMAP ホストはスキームやポートを含まないホスト名である必要があります。 |
| *Instance already connected* と表示される | 同じ URL を持つ別のインスタンスが存在します。代わりにそのインスタンスを編集してください。 |
| *API request failed (401/403)* と表示される | API キーに必要な権限がないか、IP 制限に Mail Archiver ホストが含まれていません。 |
| *API request rejected* と表示される | Mailcow が `error`/`danger`/`warning` 行を返しました。Mailcow のログを確認してください。Mail Archiver はレスポンスボディを転送しません。 |
| *IMAP verification failed* と表示される | IMAP ホストまたはポートが間違っている、信頼できない証明書を使用している、または Mailcow で app-password 機能が無効になっています。 |
| *IMAP account exists* と表示される | 独立した IMAP アカウントが既にこのアドレスをアーカイブしています。2つ目のアーカイブを作成するのではなく、そのアカウントを使用してください。 |
| *Revoke previous password* と表示される | このメールボックスのアーカイブアカウントが削除されました。まず残っているアプリパスワードを失効させてから、再度有効化してください。 |
| メールボックスが **Pending** のまま | Mailcow API がタイムアウトしました。ページをリロードしてメールボックスを再度有効化してください。重複したアプリパスワードは作成されません。 |
| 削除が拒否される | 管理対象のアプリパスワードがまだアクティブです。先にメールボックスページでそれらを失効させてください。 |

## 使用されている API エンドポイント {#api-endpoints-used}

- `GET /api/v1/get/mailbox/all`
- `GET /api/v1/get/app-passwd/all/{mailbox}`
- `POST /api/v1/add/app-passwd`
- `POST /api/v1/delete/app-passwd`

## データベースの変更 {#database-changes}

マイグレーションでは、インデックスと外部キーとともに `MailcowInstances` と `MailcowMailboxes` テーブルのみが追加されます。既存のメールボックステーブルとアーカイブデータは保持されます。アーカイブアカウントを削除すると、紐付けの `MailAccountId` が `NULL` に設定され、リモートの資格情報を後で失効させることができるようになります。

# Read-Only REST API (v1) {#read-only-rest-api-v1}

Mail Archiver поставляется с опциональным **read-only** REST API для программного доступа к архивированной почте. Он предназначен для сценариев автоматизации и интеграции (отчетность, экспорт для e-discovery, мониторинг) без использования веб-интерфейса.

Суть заключается в том, чтобы позволить скрипту или ИИ-агенту читать архивированную почту, **никогда не раскрывая учетные данные почтового ящика и не взаимодействуя напрямую с почтовым провайдером.** Ограниченный API-ключ для конкретного пользователя — это возможность *читать архив*, а не учетные данные для *стать почтовым ящиком*. Он наследует только разрешения почтового ящика своего владельца, не предоставляет прав на запись и может быть отозван мгновенно без вмешательства в основной почтовый аккаунт.

> ⚠️ **API отключен по умолчанию.** Его необходимо явно включить в конфигурации (см. [Enabling the API](#enabling-the-api)). Если API отключен, каждый маршрут `/api/*` возвращает `404 Not Found`.

API является **read-only по своей конструкции**: он предоставляет доступ к аккаунтам, папкам, поиску сообщений, деталям сообщений и загрузке вложений. Он никогда не создает, не изменяет и не удаляет данные.

## Включение API {#enabling-the-api}

API настраивается в разделе `Api` в `appsettings.json` (или через эквивалентные переменные окружения, например, `Api__Enabled=true`):

```json
"Api": {
  "Enabled": false,
  "AllowAttachmentDownloads": true,
  "AllowMessageDownloads": true,
  "EnableSwaggerUi": true,
  "DefaultPageSize": 20,
  "MaxPageSize": 100,
  "RateLimitPerMinute": 120
}
```


### Жизненный цикл ключа {#key-lifecycle}

1. **Создание (Create)** — пользователь создает ключ с описательным `Name` и необязательным сроком действия. В ответе ключ в открытом виде отображается только один раз.
2. **Использование (Use)** — ключ передается как bearer token. Каждый принятый запрос обновляет `LastUsedAt` ключа (запись ограничена максимум один раз в ~5 минут, чтобы избежать записи при каждом вызове).
3. **Истечение срока (Expire)** — если `ExpiresAt` установлен и это время уже прошло, ключ отклоняется.
4. **Отзыв (Revoke)** — владелец ключа или администратор отзывает ключ (устанавливается `RevokedAt`); ключ немедленно и навсегда отклоняется.

Ключ считается **активным (active)**, если он не отозван, не просрочен, **и** его владелец все еще активен. Если ключ не активен по любой из этих причин, он отклоняется с ошибкой `401`.

### Модель разрешений {#permission-model}

API-ключ наследует в точности те же разрешения, что и пользователь, которому он принадлежит. Аутентифицированный субъект (principal) обладает теми же правами (claims), что и при обычном веб-входе, поэтому все существующие полномочия...

| Настройка | Значение по умолчанию | Описание |
| --- | --- | --- |
| `Enabled` | `false` | Главный переключатель. Когда `false`, все маршруты `/api/*` возвращают `404`, а документы OpenAPI / Swagger UI не отображаются. |
| `AllowAttachmentDownloads` | `true` | Когда `false`, эндпоинт для скачивания вложений возвращает `403`. Метаданные о вложениях по-прежнему возвращаются эндпоинтом деталей сообщения. |
| `AllowMessageDownloads` | `true` | Когда `false`, эндпоинты полных сообщений (`/eml` и `/raw`) возвращают `403`. Полное сообщение содержит свои вложения, поэтому **и** этот переключатель, и `AllowAttachmentDownloads` должны быть `true`; отключение любого из них отключает оба эндпоинта. |
| `EnableSwaggerUi` | `true` | Когда `true` (и `Enabled` равен `true`), Swagger UI монтируется по адресу `/apidocs`, а документ OpenAPI — по адресу `/apidocs/spec/v1.json`. Оба требуют аутентифицированной **веб-сессии (cookie)** — они не являются частью `/api/` и недоступны через API-ключ. |
| `DefaultPageSize` | `20` | Размер страницы, используемый, если в запросе отсутствует `pageSize`. |
| `MaxPageSize` | `100` | Верхняя граница; значения `pageSize` больше этого значения будут ограничены данным пределом. |
| `RateLimitPerMinute` | `120` | Бюджет запросов в фиксированное окно на один API-ключ в минуту (см. [Rate limiting](#rate-limiting)). |

## Аутентификация {#authentication}

API выполняет аутентификацию с помощью **API-ключей для каждого пользователя**, передаваемых в качестве bearer-токена:

```
Authorization: Bearer ma_<43 url-safe base64 characters>
```

`/api/v1` принимает **только** API-ключи. Браузерные cookie не учитываются, поэтому у API нет поверхности для CSRF-атак. Ошибки аутентификации возвращают `401` с заголовком `WWW-Authenticate: Bearer` и телом [problem+json](#errors) — API **никогда** не перенаправляет на страницу входа.

Управление ключами осуществляется пользователями самостоятельно через веб-интерфейс в разделе **API Keys** (каждый пользователь управляет своими ключами; администраторы могут просматривать и отзывать ключи любого пользователя).

### Формат API-ключа {#api-key-format}

Ключ представляет собой строку `ma_`, за которой следуют 43 безопасных для URL base64-символа, кодирующих 32 случайных байта (256 бит энтропии):

```
ma_8Kf3pQ2sV9xT1bN6mW0rZ4yH7jL5dC8gA3eU2iO1kP
└┬┘└──────────────────────┬──────────────────────┘
prefix          43 chars base64url(32 random bytes)
```

Хранение:

- **`KeyPrefix`** — первые ~11 символов (например, `ma_8Kf3pQ2`), хранятся в открытом виде. Используются для идентификации ключа в UI и логах. Не является секретом.
- **`KeyHash`** — hex-кодированный SHA-256 полного ключа, хранящийся под **уникальным индексом**. Сам ключ в открытом виде никогда не сохраняется.

Полный ключ показывается пользователю **ровно один раз** в момент создания. Его невозможно извлечь позже; утерянный ключ необходимо отозвать и заменить.

### Жизненный цикл ключа {#key-lifecycle}

1. **Создание (Create)** — пользователь создает ключ с описанием `Name` и необязательным сроком действия. В ответе ключ в открытом виде отображается один раз.
2. **Использование (Use)** — передача ключа в качестве bearer-токена. Каждый принятый запрос обновляет `LastUsedAt` ключа (запись ограничена частотой не более одного раза в ~5 минут, чтобы избежать записи при каждом вызове).
3. **Истечение срока (Expire)** — если установлен `ExpiresAt` и это время уже прошло, ключ отклоняется.
4. **Отзыв (Revoke)** — владелец ключа или администратор отзывает ключ (устанавливается `RevokedAt`); ключ немедленно и навсегда отклоняется.

Ключ считается **активным**, если он не отозван, не просрочен, **и** его владелец все еще активен. Ключ, неактивный по любой из этих причин, отклоняется с ошибкой `401`.

### Модель разрешений {#permission-model}

API-ключ наследует те же права, что и пользователь, которому он принадлежит. Аутентифицированный субъект (principal) обладает теми же утверждениями (claims), что и при обычном входе через веб-интерфейс, поэтому вся существующая логика авторизации применяется без изменений:

- **Администраторы** (`IsAdmin`) видят все почтовые аккаунты и все сообщения.
- **Обычные пользователи** видят только назначенные им почтовые аккаунты (`UserMailAccount`). Аккаунты и сообщения вне этого набора считаются **несуществующими**: запросы к ним возвращают `404`, а не `403`, поэтому API не раскрывает факт существования аккаунтов, которые вызывающая сторона не может видеть.

### Обоснование безопасности {#security-rationale}

- **Обход 2FA.** API-ключи по своей конструкции обходят двухфакторную аутентификацию — это характерно для неинтерактивных токенов (аналогично персональным токенам доступа в GitHub/GitLab). Это минимизируется за счет того, что ключи **выключены по умолчанию**, могут быть отозваны, имеют необязательный срок действия, ограничены правами пользователя, а каждый доступ фиксируется в [журнале доступа](#access-logging).
- **Отсутствие cookie на `/api`.** Аутентификация через cookie не принимается на маршрутах `/api`, что устраняет опасения относительно CSRF для API.
- **Транспорт.** В рабочей среде API всегда должен работать через HTTPS, чтобы bearer-токены не были перехвачены при передаче.

## Конвенции {#conventions}

### Базовый URL и версионирование {#base-url-and-versioning}

Все эндпоинты находятся под `/api/v1`. Версия указана в пути, чтобы будущие
ломающие изменения могли выпускаться как `/api/v2` без нарушения работы существующих клиентов.

Ответы являются `application/json`, если не указано иное (загрузка вложений возвращает
собственный content type вложения). Все временные метки указаны в UTC, ISO 8601
(`2026-06-11T09:30:00Z`).

### Пагинация {#pagination}

Эндпоинты списков возвращают объект пагинации:

```json
{
  "items": [ /* ... */ ],
  "page": 1,
  "pageSize": 20,
  "totalItems": 137,
  "totalPages": 7
}
```

- `page` является 1-базовым. Страницы вне диапазона возвращают пустой массив `items` (не является
  ошибкой).
- `pageSize` по умолчанию равен `Api:DefaultPageSize` и ограничен значением
  `[1, Api:MaxPageSize]`.

### Ошибки {#errors}

Ошибки используют [RFC 7807](https://datatracker.ietf.org/doc/html/rfc7807)
`application/problem+json`:

```json
{
  "type": "https://datatracker.ietf.org/doc/html/rfc7231#section-6.5.1",
  "title": "Bad Request",
  "status": 400,
  "detail": "Unknown sortBy value 'foo'.",
  "instance": "/api/v1/emails"
}
```

| Статус | Когда |
| --- | --- |
| `400 Bad Request` | Некорректные параметры (например, нераспознанная дата, невалидный `sortBy`). |
| `401 Unauthorized` | Отсутствующий, некорректный, просроченный, отозванный или иным образом невалидный ключ. Включая `WWW-Authenticate: Bearer`. |
| `403 Forbidden` | Запрос на загрузку вложений во время `AllowAttachmentDownloads=false` или загрузку сообщений во время `AllowMessageDownloads=false`. |
| `404 Not Found` | Ресурс не существует **или** находится за пределами разрешенных аккаунтов вызывающей стороны. Также возвращается для каждого маршрута `/api/*` при `Api:Enabled=false`. |
| `429 Too Many Requests` | Превышен лимит запросов (Rate limit exceeded). |
| `500 Internal Server Error` | Непредвиденная ошибка сервера (problem+json, никогда не HTML-страница ошибки). |

### Ограничение частоты запросов (Rate limiting) {#rate-limiting}

Запросы ограничены политикой фиксированного окна: `Api:RateLimitPerMinute`
запросов в минуту (по умолчанию `120`), разделенных по префиксу API-ключа (с
откатом к IP-адресу клиента, если ключ отсутствует). Превышение бюджета возвращает `429`.

## Эндпоинты {#endpoints}

> Все примеры предполагают, что API включен и `$KEY` содержит валидный ключ.

### Список аккаунтов {#list-accounts}

```
GET /api/v1/accounts
```

Возвращает почтовые аккаунты, видимые вызывающему пользователю. Поля учетных данных
(IMAP/OAuth username, password, client secret, …) **никогда** не включаются в ответ.

```bash
curl -H "Authorization: Bearer $KEY" https://host/api/v1/accounts
```

```json
[
  {
    "id": 1,
    "name": "Support Mailbox",
    "emailAddress": "support@example.com",
    "provider": "IMAP",
    "isEnabled": true,
    "lastSync": "2026-06-11T08:15:00Z"
  }
]
```

### Список папок {#list-folders}

```
GET /api/v1/accounts/{id}/folders
```

Возвращает дерево папок для одного аккаунта в виде вложенной структуры. Возвращает `404`, если
аккаунт не существует или не виден вызывающему пользователю.

```json
[
  {
    "name": "INBOX",
    "fullPath": "INBOX",
    "totalCount": 4213,
    "level": 0,
    "children": [
      { "name": "Work", "fullPath": "INBOX/Work", "totalCount": 512, "level": 1, "children": [] }
    ]
  }
]
```

### Поиск сообщений {#search-messages}

```
GET /api/v1/emails
```

Выполняет поиск в архивированных сообщениях с теми же возможностями, что и веб-интерфейс.

| Параметр запроса | Тип | Описание |
| --- | --- | --- |
| `q` | string | Полнотекстовый запрос по полям subject, body, from, to, cc, bcc. Поддерживает синтаксис полей, например, `subject:invoice`, `from:alice@example.com`. |
| `from` | date | Самая ранняя дата отправки (включительно), `YYYY-MM-DD`. |
| `to` | date | Самая поздняя дата отправки (включительно), `YYYY-MM-DD`. |
| `accountId` | int | Ограничить одним аккаунтом (должен быть доступен вызывающему пользователю). |
| `folder` | string | Ограничить одной папкой по полному пути. |
| `direction` | string | `incoming` или `outgoing`. |
| `page` | int | Номер страницы (начиная с 1, по умолчанию `1`). |
| `pageSize` | int | Количество результатов на страницу (по умолчанию `Api:DefaultPageSize`, ограничено значением `Api:MaxPageSize`). |
| `sortBy` | string | Одно из значений: `sentDate` (по умолчанию), `receivedDate`, `subject`, `from`, `to`. |
| `sortOrder` | string | `asc` или `desc` (по умолчанию `desc`). |

Возвращает [пагинированную оболочку](#pagination) со списком [`EmailSummaryDto`](#emailsummarydto).
Создает запись в [журнале доступа](#access-logging) типа `Search`.

```bash
curl -H "Authorization: Bearer $KEY" \
  "https://host/api/v1/emails?q=subject:invoice&from=2026-01-01&pageSize=50"
```

```json
{
  "items": [
    {
      "id": 9876,
      "accountId": 1,
      "subject": "Invoice #4711",
      "from": "billing@vendor.com",
      "to": "support@example.com",
      "sentDate": "2026-03-02T11:04:00Z",
      "isOutgoing": false,
      "hasAttachments": true,
      "folderName": "INBOX"
    }
  ],
  "page": 1,
  "pageSize": 50,
  "totalItems": 3,
  "totalPages": 1
}
```

### Get message {#get-message}

```
GET /api/v1/emails/{id}
```

Возвращает полное сообщение, включая тела (bodies). Для тела используется та же цепочка фолбэков, что и в веб-интерфейсе: `OriginalBodyHtml` (сырые байты) → `BodyUntruncatedHtml` →
`HtmlBody`, и эквивалентная для текстового тела. Возвращает `404`, если сообщение
не существует или принадлежит аккаунту, на который у вызывающей стороны нет прав доступа. Создает запись в журнале доступа типа `Open`.

Возвращает [`EmailDetailDto`](#emaildetaildto).

### Скачивание вложения {#download-attachment}

```
GET /api/v1/emails/{id}/attachments/{attachmentId}
```

Передает байты вложения с его сохраненным типом контента и именем файла. Возвращает
`404`, если сообщение или вложение не существует или не доступно вызывающему пользователю. Возвращает `403` (problem+json), когда `Api:AllowAttachmentDownloads=false`.
Записывает запись в лог доступа типа `Download`.

```bash
curl -H "Authorization: Bearer $KEY" -OJ \
  https://host/api/v1/emails/9876/attachments/12
```

### Скачивание сообщения (.eml) {#download-message-eml}

```
GET /api/v1/emails/{id}/eml
```

Возвращает сообщение в формате `message/rfc822`, воссозданное из архивированных полей:
адресов, сохраненных сырых заголовков (`Received`, `Authentication-Results`,
`X-Spam-*`, …), тел и вложений. Работает для каждого архивированного письма. Это
та же реконструкция, которую выдает экспорт аккаунта в веб-интерфейсе, поэтому она **не**
является байт-в-байт идентичной полученному сообщению: подписи DKIM не пройдут проверку.
Для этого используйте [`/raw`](#download-original-message).

Возвращает `404`, если сообщение не существует или не видно вызывающему пользователю, и
`403` (problem+json), когда `Api:AllowMessageDownloads=false`. Создает запись в журнале доступа типа `Download`.

```bash
curl -H "Authorization: Bearer $KEY" -OJ \
  https://host/api/v1/emails/9876/eml
```

### Скачать исходное сообщение {#download-original-message}

```
GET /api/v1/emails/{id}/raw
```

Возвращает исходное сообщение в том виде, в котором оно было получено (`message/rfc822`), для анализа спама,
проверки DKIM или форензики. Оригинал сохраняется только в том случае, если в момент
архивации письма был установлен параметр `RawMessages:Enabled`; см.
[Original Message Storage Settings](Setup.md#-original-message-storage-settings).
Наличие оригинала у письма отображается через `hasRawMessage` в
[`EmailDetailDto`](#emaildetaildto).

| Заголовок ответа | Значение |
| --- | --- |
| `X-Raw-Message-Sha256` | SHA-256 возвращаемых байтов, записанный при сохранении сообщения |
| `X-Raw-Message-Source` | `imap`, `graph`, `eml-file` (точные копии) или `serialized` (переписано парсером, окончания строк нормализованы до CRLF) |
| `X-Raw-Message-Storage` | `postgres` или `filesystem` — источник, из которого были прочитаны байты (см. [Storage backend](RawMessages.md#storage-backend)) |

Байты могут находиться в базе данных или в файле, в зависимости от
`RawMessages:Storage` на момент архивации сообщения; эндпоинт
определяет это для каждого сообщения отдельно, поэтому оба типа обрабатываются одинаково. При
`RawMessages:FileSystem:VerifyChecksumOnRead` (по умолчанию `true`) файл
повторно хешируется перед отправкой, и сообщение, содержимое которого больше не соответствует
записанной контрольной сумме, **не** будет выдано.

Возвращает `404`, если сообщение не существует или не видно вызывающему субъекту,
`404` с заголовком ошибки `No original message is stored for this email.`,
если сообщение существует, но без оригинала, и `500` с заголовком
`Stored original message failed its checksum.`, если сохраненное содержимое больше не
соответствует контрольной сумме, записанной в момент архивации. Возвращает `403` (problem+json), когда
`Api:AllowMessageDownloads=false`. Записывает запись в лог доступа типа `Download`.

```bash
curl -H "Authorization: Bearer $KEY" -o 9876.eml \
  https://host/api/v1/emails/9876/raw
sha256sum 9876.eml          # matches X-Raw-Message-Sha256
spamassassin -t < 9876.eml  # or: rspamc < 9876.eml
```

### Статистика {#stats}

```
GET /api/v1/stats
```

Возвращает агрегированную статистику архива, доступную вызывающему объекту: общее количество архивированных
сообщений, доступных почтовых аккаунтов, вложений в этих сообщениях и общий
размер базы данных PostgreSQL в мегабайтах. Для пользователей без прав администратора значения
ограничены почтовыми аккаунтами, закрепленными за ними (то же ограничение применяется к
веб-панели управления); администраторы видят общие показатели.

Для API-ключей без прав администратора `databaseSizeInMB` является пустой строкой: размер
базы данных описывает весь экземпляр, а не область действия ключа. Сообщения, Аккаунты и
Вложения всегда ограничены аккаунтами, к которым ключ может иметь доступ.

```bash
curl -H "Authorization: Bearer $KEY" https://host/api/v1/stats
```

```json
{
  "emails": 160132,
  "accounts": 4,
  "attachments": 43540,
  "databaseSizeInMB": "5432"
}
```

### StatsDto {#statsdto}

| Field | Type | Notes |
| --- | --- | --- |
| `emails` | int | Количество архивированных сообщений, видимых вызывающему пользователю |
| `accounts` | int | Количество почтовых аккаунтов, видимых вызывающему пользователю |
| `attachments` | int | Количество вложений в видимых сообщениях |
| `databaseSizeInMB` | string | Полный размер базы данных PostgreSQL в МБ; пусто для ключей без прав администратора |

## Логирование доступа {#access-logging}

Каждый случай доступа к данным через API записывается в тот же журнал доступа, который используется веб-интерфейсом (доступен в разделе **Logs**), и привязывается к пользователю, владеющему ключом:

## OpenAPI и Swagger UI {#openapi-and-swagger-ui}

Когда API включен и `Api:EnableSwaggerUi=true`:

- Документ OpenAPI v1 доступен по адресу **`/apidocs/spec/v1.json`**.
- Swagger UI доступен по адресу **`/apidocs`**.

Оба пути находятся за пределами `/api/` и, следова следовательно, защищены обычной веб-аутентификацией (cookie) — для их просмотра требуется сессия авторизованного пользователя в браузере, и к ним нельзя получить доступ с помощью API key.

# 📥 Web UIでのメールのインポート (EML / MBox) {#importing-mail-in-the-web-ui-eml-mbox}

[← ドキュメントインデックスに戻る](index.md)

## 📋 概要 {#overview}

[コマンドラインインターフェース](CLI.md)や[CSVアカウントインポート](Account-Import.md)に加えて、Mail Archiverは**Webインターフェースを通じて**既存のメールアーカイブをインポートできます。アップロードフォームは2種類あります。

| フォーム | 受付ファイル | 結果 |
|------|---------------|--------|
| **Import MBox** | `.mbox`, `.mbx` | ファイル内のすべてのメッセージが、選択した**1つ**のフォルダにインポートされます |
| **Import EML** | `.eml`を含む`.zip` | **ZIP内のフォルダ構造**によって、各メッセージの保存先が決まります |

どちらのフォームも、既存のMail Archiverアカウントにメッセージをアーカイブし、どちらも**バックグラウンドジョブ**として実行され、どちらも**重複を自動的にスキップ**します。つまり、同じファイルを2回インポートしても、2つ目のコピーは作成されません。

> 💡 **ヒント**: アーカイブがすでにサーバー上のファイルとして存在する場合は、[CLI](CLI.md)を使用することをお勧めします。ブラウザ経由のアップロードを回避でき、数GB規模のアーカイブにはこちらの方が適しています。

## 🧭 アクセス方法 {#access}

1. メインメニューで **Mail Accounts** を開きます。
2. アカウントリストの上にある **Import** ドロップダウンを使用し、**Import MBox** または **Import EML** を選択します。

これらのフォームは、**管理者**（すべてのアカウント）および**セルフマネージャー**（自身に割り当てられたアカウント）が利用可能です。詳細は [User Management](UserManagement.md#-user-account-permissions) を参照してください。インポート先として選択できるのは、**有効化（enabled）**されているアカウントのみです。無効化されたアカウントは選択できません。

## 📨 Import MBox {#import-mbox}

MBoxは、エクスポートされたフォルダや`mbox`スタイルのバックアップにおいて、ほとんどのメールクライアントで使用されている形式です。

| フィールド | 意味 |
|-------|---------|
| **MBox File** | アップロードする`.mbox` / `.mbx`ファイル |
| **Target Account** | メッセージを受け取るMail Archiverアカウント |
| **Target Folder** | メッセージがインポートされるフォルダ。アカウントの既存のフォルダリストから1つ選択するか、新しい名前を入力してください。まだ存在しないフォルダは、インポート中に**自動的に作成**されます。デフォルトは `INBOX` です。 |

ファイル内のすべてのメッセージは、その単一のターゲットフォルダにインポートされます。MBoxファイル自体にはフォルダ情報が含まれていないため、元のメールボックスの構造は再構築されません。構造を維持する必要がある場合は、EML/ZIPルートを使用してください。

## 🗂️ Import EML {#import-eml}

EMLインポートでは、エントリが`.eml`ファイルである**ZIPアーカイブ**を想定しています。

- ZIPの**ルート**にある `.eml` ファイルは `INBOX` にインポートされます。
- **サブフォルダ**にある `.eml` ファイルは、そのサブフォルダと**同じ名前**のフォルダにインポートされます。

したがって、次のような構成のZIPの場合：

```
mailbox.zip
├── 2024-invoice.eml            → INBOX
├── Archive/
│   └── old-message.eml         → Archive
└── Projects/
    └── 2026/
        └── kickoff.eml         → Projects/2026
```

フォルダツリーとメッセージが共に復元されます。個別の `.eml` ファイルは、まずZIPにまとめることで（`zip emails.zip *.eml`）アップロードできます。

## ⚙️ 共通の動作 {#shared-behaviour}

**Start Import** を押すと、どちらのフォームも同様に動作します。

- **ファイルサイズ制限** — `Upload__MaxFileSizeGB` で設定されます（デフォルトは **10 GB**）。フォームのファイルピッカーの横に現在の制限が表示されます。
- **バックグラウンド処理** — アップロードはジョブとしてキューに入れられます。ブラウザを開き続ける必要はありません。
- **重複の処理** — すでにアーカイブ内にあるメッセージはスキップされ、別途カウントされます。重複は `Message-ID` ヘッダーに基づいて照合されます。
- **不正な入力** — 読み取り不可能なファイルは個別にスキップされ、インポート全体を中断するのではなく、ステータスページに報告されます。
- **進捗状況** — ジョブID、ファイル名、ファイルサイズ、ステータス、処理済み/合計メッセージ数、および実行中のカウントが表示されるジョブステータスページに直接移動します。同じジョブは [Jobs](BackgroundJobs.md) ページにも表示されます。
- **キャンセル** — 実行中のインポートは、そのステータスページからキャンセルできます。その時点までにインポートされたメッセージはアーカイブに残ります。
- **監査証跡** — インポート内容は [access log](Logs.md) に記録され、その後、アカウントごとのストレージ値が更新されます（[Per-Account Storage](AccountStorage.md) を参照）。

### ジョブステータス {#job-statuses}

`Queued` → `Running` → `Completed` / `Failed` / `Cancelled`

完了したジョブでは、いくつのメッセージがインポートされ、いくつが失敗し、いくつが重複としてスキップされたかが報告されます（例: *"1420 imported, 3 failed, 87 duplicates"*）。インポートが成功すると、アップロードされたファイルはサーバーから削除されます。失敗したエントリは、何が拒否されたかを確認できるように、ジョブの有効期間中保持されます。

## ⚠️ 注意事項 {#things-to-watch-out-for}

- **誤ったファイル形式** — 拡張子が `.mbox`、`.eml`、または `.zip` のいずれかでない限り、アップロードは拒否されます。EMLフォームのピッカーは `.zip` のみを、MBoxフォームは `.mbox` と `.mbx` のみを許可します。
- **"0 imported, N duplicates"** — これはエラーではありません。メッセージはすでにアーカイブ内に存在しており、おそらく以前のインポートまたは同じソースの同期によるものです。
- **非常に大きなアーカイブ** — MBoxファイルはメッセージごとに読み込まれるため、数GBのファイルはバックグラウンドであっても時間がかかります。再アップロードするのではなく、ステータスページで進捗を確認してください。
- **空きディスク容量** — アップロードされたファイルはサーバーに一時的に保存され、アーカイブデータベースの隣に容量が必要です。
- **特殊文字を含むフォルダ名** — フォルダ名はZIPのパスまたは入力から取得されます。特殊な文字を使用した場合は、インポート後にアカウントのフォルダリストを確認してください。

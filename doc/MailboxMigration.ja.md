# 📥 Mailbox Migration Guide {#mailbox-migration-guide}

[← Back to Documentation Index](index.md)

このガイドでは、Mail Archiver アプリケーションを使用して、あるメールプロバイダーから別のメールプロバイダーへメールボックスを移行する方法について説明します。

## 📋 Overview {#overview}

Mail Archiver アプリケーションは、ソースメールボックスからターゲットメールボックスへメールを移行する機能を提供します。これは、メールの履歴を保持したままメールプロバイダーを変更する場合に特に有用です。移行中、ソースメールボックスのフォルダ構造も保持されます。

> **最近のメールのみを移行する場合：** 以下に説明するフローは、アーカイブされたメールボックスの*すべて*をコピーするため、2回実行するとすべてが2回目に追加されてしまいます。フル履歴をアーカイブに残したまま、新しいメールボックスに特定の期限以降のメールのみを保持したい場合は、代わりに [date-windowed offload](Offload.md) を使用してください。これは日付範囲を指定でき、フォルダの除外や名前変更が可能で、ドライランも提供されます。また、ターゲットが既に保持しているものはスキップするため、繰り返し実行しても安全です。コマンドラインからも操作できるため、大量のメールボックスをスクリプトで処理することも可能です。

## 🚀 Migration Process {#migration-process}

以下の手順に従って、メールボックスを移行してください：

1. **ソースアカウントの追加**
   - "Email Accounts" セクションに移動します
   - "Add Account" をクリックします
   - ソースアカウントの詳細と認証情報を入力します
   - アカウントを保存します

2. **ソースアカウントの同期**
   - アプリケーションがソースアカウントからすべてのメールを同期するのを許可します
   - 同期プロセスが完了するまで待ちます

3. **ターゲットアカウントの追加**
   - "Email Accounts" セクションで、"Add Account" をクリックします
   - ターゲットアカウントの詳細と認証情報を入力します
   - アカウントを保存します

4. **ターゲットアカウントの同期**
   - ターゲットアカウントが新しい場合は、正しくセットアップされていることを確認するために同期を行います
   - 同期プロセスが完了するまで待ちます

5. **移行の開始**
   - "Email Accounts" セクションで、ソースアカウントを特定します
   - アカウントの詳細に移動します
   - "Copy All Emails to Another Mailbox" オプションを選択します
   - ターゲットアカウントとターゲットフォルダを選択します
   - **"Preserve Folder Structure"** オプションを有効にします。これにより、選択したターゲットフォルダがルートとなり、その下にソースのフォルダ構造全体が再帰的に再作成されます
   - このオプションを有効にしない場合、すべてのメールは選択したターゲットフォルダに直接配置されます（サブフォルダなしのフラットな状態）
   - 移行プロセスを開始します

6. **移行の監視**
   - メール数が大量にある場合、移行はバックグラウンドタスクとして実行されます
   - 移行のステータスと進捗は "Jobs" タブで確認できます
   - 移行が正常に完了するまで待ちます

7. **ソースアカウントの無効化**
   - 転送が成功した後、ソースアカウントに戻ります
   - アカウント設定でソースアカウントを "Disabled" に設定します
   - これにより、将来的にアーカイブされないようになります

## ⚠️ Important Notes {#important-notes}

- このフローは繰り返し実行できません。再度実行すると、すべてのメッセージが2回目として追加されます。繰り返し可能な代替手段としては [date-windowed offload](Offload.md) があります。
- ソースアカウントにすべてのメールを読み取るための十分な権限があることを確認してください
- ターゲットアカウントに、移行されるメールのための十分なストレージ容量があることを確認してください
- 移行プロセスは、メールの数や接続速度によって時間がかかる場合があります
- メールサービスへの影響を最小限に抑えるため、オフピークの時間帯に移行を実行することをお勧めします
- プロセスが進んでいることを確認するために、"Jobs" タブで定期的に移行ステータスを確認してください
- 移行後、すべてのメールがターゲットアカウントに正常に転送されたことを確認してください

## ✅ Best Practices {#best-practices}

- メールボックス全体を移行する前に、必ず少数のメールのサブセットで移行プロセスをテストしてください
- 移行を開始する前に、重要なメールのバックアップを保持してください
- メールの使用量が最小限になる時間帯に移行をスケジュールしてください
- 移行の進捗を注意深く監視し、発生する可能性のある問題に対処できるように準備してください
- 移行が完了したら、すべてのメールが正しく転送され、アクセス可能であることを確認してください

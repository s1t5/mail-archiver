## 🌐 Обзор {#overview}

Приложение Mail Archiver поддерживает учетные записи Microsoft 365 (M365), используя поток учетных данных клиента (OAuth2 client credentials flow) для извлечения электронной почты. Кроме того, оно предоставляет функционал политики хранения для автоматического удаления писем с почтового сервера по истечении указанного периода, что помогает управлять дисковым пространством при сохранении полного архива.

## ☁️ Регистрация приложения Azure для извлечения электронной почты {#azure-app-registration-for-email-retrieval}

### 🛠️ Предварительные требования {#prerequisites}

- Административный доступ к Microsoft Entra ID (Azure AD)
- Тенант Microsoft 365 с лицензиями Exchange Online

### 🚀 Создание регистрации приложения {#create-app-registration}

1. Перейдите в [Microsoft Entra Admin Center](https://entra.microsoft.com)
2. Войдите под своей учетной записью администратора
3. В левой навигационной панели выберите **App registrations**
4. Нажмите **+ New registration** в верхней части страницы App registrations
5. Заполните следующие сведения:
   - **Name**: Введите описательное имя (например, "Mail Archiver M365 Provider")
   - **Supported account types**: Выберите **Accounts in this organizational directory only** (Single tenant)
     - Это необходимо для потока учетных данных клиента, используемого Mail Archiver
   - **Redirect URI**: Оставьте это поле пустым (не требуется для потока учетных данных клиента)
6. Нажмите **Register**

**Важно**: Запишите следующие значения со страницы **Overview**:
- **Application (client) ID** — вам понадобится это значение как `ClientId` в Mail Archiver
- **Directory (tenant) ID** — вам понадобится это значение как `TenantId` в Mail Archiver

### 🔐 Настройка необходимых разрешений API {#set-required-api-permissions}

1. Перейдите в раздел **API permissions** в левом меню
2. Нажмите **+ Add a permission**
3. Выберите **Microsoft Graph**
4. Выберите **Application permissions** (требуется для потока учетных данных клиента Mail Archiver)
5. Добавьте следующие разрешения:
   - **Mail.Read** — чтение почты во всех почтовых ящиках
   - **Mail.ReadWrite** — чтение и запись почты во всех почтовых ящиках (для функции восстановления, а также удаления)
   - **User.Read.All** — чтение полных профилей всех пользователей (требуется для импорта почтовых ящиков тенанта Microsoft 365; также предоставляет `assignedPlans` для фильтрации лицензий Exchange)

6. Нажмите **Add permissions**
7. **КРИТИЧЕСКИ ВАЖНО**: Нажмите **Grant admin consent for [Your Organization]**
8. Подтвердите действие, нажав **Yes**

**Примечание**: Разрешения приложения (Application permissions) необходимы, так как Mail Archiver использует поток учетных данных клиента для доступа к почтовым ящикам без участия пользователя.

### 🔑 Генерация секрета клиента {#generate-client-secret}

1. Перейдите в раздел **Certificates & secrets** в левом меню
2. В подразделе **Client secrets** нажмите **+ New client secret**
3. Укажите описание (например, "Mail Archiver Secret")
4. Выберите период действия (expiration period)
5. Нажмите **Add**
6. **Важно**: Немедленно скопируйте значение **Value** и сохраните его в безопасном месте. Это значение больше не будет показано.

## 📧 Настройка учетной записи Mail Archiver M365 {#configure-mail-archiver-m365-account}

После завершения регистрации приложения вам необходимо настроить почтовый аккаунт M365 в Mail Archiver со следующими значениями:

### 📋 Необходимые значения из регистрации приложения: {#required-values-from-app-registration}

1. **Client ID**: Скопируйте **Application (client) ID** со страницы **Overview** регистрации приложения
2. **Client Secret**: Скопируйте **Value**, которое вы сохранили при создании секрета клиента
3. **Tenant ID**: Скопируйте **Directory (tenant) ID** со страницы **Overview** регистрации приложения

### 🚀 Создание аккаунта M365 в Mail Archiver: {#creating-m365-account-in-mail-archiver}

1. Войдите в приложение Mail Archiver
2. Перейдите в **Mail Accounts** > **Create**
3. Заполните следующие поля:
   - **Name**: Описательное имя аккаунта (например, "Sales Team M365")
   - **Email Address**: Целевой адрес электронной почты ящика для архивации
   - **Provider**: Выберите **M365**
   - **Client ID**: Введите Application (client) ID из вашей регистрации приложения
   - **Client Secret**: Введите сохраненное значение секрета клиента
   - **Tenant ID**: Введите Directory (tenant) ID из вашей регистрации приложения

4. Нажмите **Create**

### ⚠️ Важные примечания: {#important-notes}

- Поле **Email Address** должно содержать фактический адрес почтового ящика, который вы хотите архивировать, при создании одиночного аккаунта M365.
- Регистрация приложения должна иметь разрешения на доступ к указанному почтовому ящику.
- Для одновременного создания аккаунтов для всех или выбранных почтовых ящиков в тенанте используйте руководство [Microsoft 365 Tenant Mailbox Import](M365TenantImport.md).


## 🗑️ Настройка политики хранения {#retention-policy-setup}

Приложение Mail Archiver предоставляет функционал политики хранения для автоматического удаления электронных писем с IMAP-сервера после того, как они были успешно архивированы, что помогает управлять дисковым пространством на IMAP-сервере при сохранении полного архива.

### 🛠️ Настройка политики хранения {#configure-retention-policy}

1. Перейдите в раздел **Mail Accounts** в приложении Mail Archiver
2. Создайте новый аккаунт M365 или отредактируйте существующий
3. В форме конфигурации аккаунта найдите поле **Delete After Days**
4. Введите количество дней, по истечении которых архивированные письма должны быть удалены с сервера:
   - Например, введите `30`, чтобы удалять письма через 30 дней
   - Оставьте поле пустым, чтобы отключить автоматическое удаление
5. Сохраните конфигурацию аккаунта


## ℹ️ Информация относительно мигрированных почтовых ящиков {#ℹ-information-regarding-migrated-mailboxes}

### 📁 Папки, невидимые после миграции {#folders-not-visible-after-migration}

Если вы перенесли свой почтовый ящик из другого почтового провайдера в Microsoft 365, некоторые папки могут не отображаться в списке папок.

#### 🔍 Причина {#background}

Mail Archiver извлекает информацию о папках из почтовых ящиков M365 через Microsoft Graph API. Приложение корректно запрашивает все доступные папки (включая скрытые) и обходит всю иерархию папок.

Однако Microsoft Graph API возвращает только те папки, у которых `PR_CONTAINER_CLASS` установлено в значение `IPF.Note`. При миграции почтовых ящиков из других почтовых систем папкам может быть присвоен другой класс контейнера, такой как `IPF.Imap`. Эти папки не отображаются через конечные точки перечисления папок Graph API.

Это поведение характерно для всех приложений, использующих данный API для извлечения папок.

#### 🔧 Варианты решения {#workaround-options}

**Вариант 1: Использование инструмента MFCMAPI (Рекомендуется)**

1. Скачайте [MFCMAPI](https://github.com/Microsoft/mfcmapi/) из официального репозитория Microsoft
2. Запустите MFCMAPI и подключитесь к вашему почтовому ящику
3. Перейдите к каждой отсутствующей папке
4. Измените свойство `PR_CONTAINER_CLASS` с `IPF.Imap` на `IPF.Note`
5. Перезапустите Outlook и обновите список папок в Mail Archiver

**Вариант 2: Пересоздание папок в Outlook**

1. Создайте новые папки непосредственно в Outlook (они будут иметь правильный класс `IPF.Note`)
2. Переместите все письма из мигрированных папок в новые папки
3. Удалите старые мигрированные папки, если это необходимо

**Вариант 3: Скрипт PowerShell (Для массовых изменений)**

Для почтовых ящиков с большим количеством мигрированных папок вы можете использовать PowerShell с модулем Exchange Online, чтобы изменить класс контейнера для нескольких папок одновременно. Обратитесь к вашему администратору Exchange за помощью в реализации этого подхода.

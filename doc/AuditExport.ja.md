# 📤 Audit Data Export {#audit-data-export}

[← Documentation Index に戻る](index.md)

## 📋 概要 {#overview}

監査データエクスポートは、既存のアーカイブから表形式の大量データパッケージ（`INDEX.XML` + CSVテーブル + インデックスDTDを含むZIP）を作成します。これらのパッケージは、データメディア受け渡し用に確立されたインデックス構造に従っており、このインデックス形式をサポートする一般的な外部監査・分析ツールによって直接インポートできます。

この機能は、**Logs ページからアクセス可能な専用ページ**として提供されており、管理者ユーザーに限定されています。すべてのエクスポート実行はアクセスログに記録されるため、エクスポート履歴はリビジョンセーフです。

## 🧭 アクセス {#access}

1. 管理者ユーザーとしてログインします
2. **Logs** ページを開きます
3. 右上の **Audit Data Export** ボタンをクリックします

管理者以外のユーザーにはボタンが表示されず、エクスポートのエンドポイントを呼び出すこともできません（サーバーによって拒否されます）。

## 📦 エクスポートパッケージの構造 {#export-package-structure}

生成された ZIP ファイルの名前は `audit-export-<timestamp>.zip` で、以下が含まれます：

| ファイル | 内容 |
|---|---|
| `INDEX.XML` | データサプライヤー、メディア、およびすべてのテーブル/カラム定義を記述するインデックスファイル |
| `index.dtd` | インデックスファイルが参照する DTD。インポートツールでの検証に必要です |
| `emails.csv` | 選択された期間/メールボックス内のアーカイブされたメール1通につき1行 |
| `attachments.csv` | オプション。エクスポートされたメールの添付ファイル1つにつき1行 |

### テーブル `emails.csv` {#table-emailscsv}

カラム（ヘッダー行なし。カラム名は、この形式の慣習通り `INDEX.XML` から取得されます）：

| カラム | 説明 |
|---|---|
| Id | 内部メールID (数値) |
| MessageId | メールの Message-ID ヘッダー |
| SentDate | 送信日、ISO 8601 UTC (`yyyy-MM-ddTHH:mm:ssZ`) |
| ReceivedDate | 受信日、ISO 8601 UTC |
| IsOutgoing | `1` = 送信済み, `0` = 受信済み |
| From | 送信者 |
| To | 受信者 |
| Cc | CC 受信者 |
| Bcc | BCC 受信者 |
| Subject | 件名 |
| FolderName | メールがアーカイブされているフォルダ |
| HasAttachments | `1` = 添付あり, `0` = 添付なし |
| AttachmentCount | 添付ファイルの数 (数値) |
| AccountEmail | アーカイブ用メールボックスのメールアドレス |

### テーブル `attachments.csv` {#table-attachmentscsv}

| カラム | 説明 |
|---|---|
| EmailId | 添付ファイルが属するメールの内部ID (`emails.csv` への結合キー) |
| FileName | 添付ファイル名 |
| ContentType | MIME タイプ |
| Size | バイト単位のサイズ (数値) |
| Sha256 | コンテンツの SHA-256 ハッシュ (コンテンツアドレス指定の添付ファイルストレージから取得) |

### CSV の規約 {#csv-conventions}

- エンコーディング: BOM なしの UTF-8 (`INDEX.XML` 内で `UTF8` として宣言)
- カラム区切り文字: `;`
- テキスト囲み文字: `"` (エスケープには二重に使用)
- レコード区切り文字: `\n` (`INDEX.XML` 内で明示的に宣言)
- 日付: ISO 8601、時刻は設定された表示タイムゾーンから UTC に変換
- ヘッダー行なし、ローカライズされた数値なし (数値カラムにはプレーンな整数が含まれます)

## 🖥️ エクスポートページの使用方法 {#using-the-export-page}

### フォームフィールド {#form-fields}

1. **From / To date** - エクスポートする期間 (必須、最大スパンは設定可能、デフォルトは10年)
2. **Mailbox** - エクスポートを単一のメールボックスに制限するか、すべてのメールボックスをエクスポートするかを選択
3. **Attachment metadata** - チェックを入れると、パッケージに `attachments.csv` が追加されます
4. **Data supplier name / location / comment** - `INDEX.XML` の `DataSupplier` ブロックに書き込まれます。`AuditExport` の設定セクションから事前入力されますが、エクスポートごとに編集可能です

### ジョブのライフサイクル {#job-lifecycle}

1. **Start Export** をクリックすると、期間とメールボックスが検証され、ジョブが作成されてページに戻ります
2. ジョブはバックグラウンドで実行されます (キューに溜まったエクスポートは順次処理されます)。ジョブテーブルには、自動ポーリングを介してライブの進捗状況 (プログレスバー付きの処理済み/合計メール数) が表示されます
3. エクスポートが完了すると、ジョブ行に **Download** ボタンが表示されます
4. 実行中またはキューにあるジョブは **キャンセル** できます

### エクスポート履歴 {#export-history}

フォームの下にある履歴テーブルには、タイムスタンプ、ユーザー、期間、メールボックス、メール数、ステータス、ファイルサイズとともに、最新のエクスポートがリストされます。履歴は **データベースに永続化** される (`AuditExportJobs` テーブル) ため、アプリケーションの再起動後も保持され、リビジョンセーフです。

ダウンロードファイルは、設定可能な保持期間 (デフォルト 30 日、`AuditExport__RetentionDays` を参照) 동안保持されます。その後、履歴行は残りますが、ZIP ファイルは日次のクリーンアップによって削除されます。

> 📝 **注意**: エクスポートファイルはアプリケーションコンテナ内に保存されます。長期的に保持する必要がある場合は、ファイルをダウンロードして監査証拠リポジトリに保存してください。

## 🔐 監査 {#auditing}

すべてのエクスポートは、新しいタイプ **Audit Data Export** のアクセスログエントリを2つ生成します：

1. **Start entry** - エクスポートがキューに追加されたとき (ジョブID、期間、メールボックス、オプションを JSON として含む)
2. **Result entry** - エクスポートが完了、失敗、またはキャンセルされたとき (ジョブID、期間、メールボックス、メール数、結果、パッケージサイズを JSON として含む)

これらのエントリは、他のすべてのアクセスログエントリと同様に Logs ページに表示され、新しいタイプでフィルタリングできます。タイプのフィルタ用ドロップダウンには自動的に反映されます。

## ⚙️ 設定 {#configuration}

`appsettings.json` 内の `AuditExport` セクション (環境変数は二重アンダースコア構文を使用します。例: `AuditExport__RetentionDays`):

| 設定 | 説明 | デフォルト |
|---|---|---|
| `DataSupplierName` | データサプライヤー名のフォームフィールドのデフォルト値 | 空 |
| `DataSupplierLocation` | データサプライヤーの場所のフォームフィールドのデフォルト値 | 空 |
| `Comment` | コメントのフォームフィールドのデフォルト値 | 空 |
| `OutputDirectory` | 生成された ZIP ファイルのディレクトリ (相対パスはアプリのコンテンツルートに対して解決されます) | `exports/audit` |
| `RetentionDays` | 完了したエクスポートファイルが削除されるまでの日数 | `30` |
| `MaxRangeYears` | 期間の開始日と終了日の間に許可される最大スパン | `10` |

## 🗄️ データベース {#database}

エクスポート履歴は `mail_archiver."AuditExportJobs"` テーブルに保存されます (マイグレーション `MigrateV2609_1` によって作成され、起動時に自動的に適用されます)。この機能によって既存のテーブルが変更されることはありません。

## 🔍 トラブルシューティング {#troubleshooting}

| 問題 | 原因 / 解決策 |
|---|---|
| 再起動後にダウンロードボタンが表示されない | エクスポートファイルはコンテナ内に存在します。コンテナが再作成されたか、保持期間が経過した場合、履歴行は残りますが ZIP は消失します。エクスポートを再実行してください。 |
| "The period must not exceed X years" | 期間を短くするか、`AuditExport__MaxRangeYears` を上げてください。 |
| ジョブが長時間 *Running* のままになる | 大規模なアーカイブは 1000 通のメールのバッチ単位でストリーミングされます。進捗は継続的に更新されます。非常に長い期間の場合、時間がかかることがあります。処理済み/合計のカウンターを確認してください。 |
| インポートツールがエンコーディングの問題を報告する | パッケージは、宣言された `UTF8` フラグと明示的なレコード区切り文字を持つ BOM なしの UTF-8 です。ツールがデータファイルの隣にある `INDEX.XML` を読み取っていることを確認してください (ZIP 全体を展開し、ZIP 内から個別にファイルを開かないでください)。 |

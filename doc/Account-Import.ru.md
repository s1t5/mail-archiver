# Импорт учетных записей {#account-import}

[← Вернуться к индексу документации](index.md)

## Обзор {#overview}

Mail Archiver поддерживает импорт нескольких учетных записей электронной почты одновременно, чтобы процесс подключения большого количества почтовых ящиков не требовал создания каждой учетной записи по отдельности.

Существует два способа массового импорта, в зависимости от почтового провайдера:

| Провайдер | Метод массового импорта | Документация |
|---|---|---|
| **Microsoft 365 (tenant)** | Обнаружение тенанта через Microsoft Graph — одна регистрация приложения обеспечивает доступ ко всем почтовым ящикам в тенанте | [Microsoft 365 Tenant Mailbox Import](M365TenantImport.md) |
| **IMAP** | Массовый импорт через CSV — загрузка CSV-файла, где на каждый почтовый ящик приходится одна строка | Эта страница (см. ниже) |

> **Примечание:** Личные учетные записи Microsoft (Outlook.com / M365 Family, провайдер **MSA**) используют интерактивный процесс авторизации через код устройства (device-code) и не могут быть импортированы массово. Их необходимо создавать и авторизовывать по одной. См. [MSA Outlook Setup](MSA_Outlook_Setup.md).

## Массовый импорт IMAP через CSV {#imap-csv-bulk-import}

### Что это делает {#what-it-does}

Массовый импорт через CSV позволяет администратору создавать сотни IMAP-аккаунтов за одну операцию путем загрузки CSV-файла. Каждая строка в файле соответствует одному почтовому ящику. Общие настройки сервера (IMAP host, port, SSL) можно указать один раз в форме загрузки, и они будут применяться ко всем строкам, при этом возможны переопределения для отдельных строк.

Импорт доступен **только администратору**. Он доступен на странице **Mail Accounts** через выпадающий список **Import** → **CSV Bulk Import**.

### Формат CSV-файла {#csv-file-format}

Файл должен быть в кодировке UTF-8, иметь **строку заголовков** и использовать **запятую (`,`) в качестве разделителя**. Поля, содержащие запятые или кавычки, должны быть заключены в двойные кавычки (`"..."`).

#### Столбцы {#columns}

| Столбец | Обязательно | Описание |
|---|---|---|
| `email` | Да | Адрес почтового ящика. Также используется в качестве логина по умолчанию, если `username` не предоставлен. |
| `password` | Да | Пароль для входа в IMAP. Хранится в исходном виде — пробелы в начале и в конце сохраняются. |
| `name` | Нет | Отображаемое имя аккаунта. Если пропущено, используется `{prefix} - <{email}>` по умолчанию. |
| `username` | Нет | Имя пользователя (логин), если оно отличается от адреса электронной почты. |
| `imap_server` | Нет | IMAP host для конкретной строки. Переопределяет общий сервер из формы загрузки. |
| `imap_port` | Нет | IMAP port для конкретной строки (1–65535). Переопределяет общий порт. |
| `use_ssl` | Нет | Переключатель SSL для строки (`true` или `false`). Переопределяет общую настройку. |

#### Пример {#example}

```csv
email,password,name,username,imap_server,imap_port,use_ssl
alice@firma.de,secret123,Alice Müller,,,,,
bob@firma.de,p@ssw0rd,,bob@firma.de,,,993,
charlie@extern.de,pass3,,charlie,mail.extern.de,143,false
```

- Строка 1 использует общий сервер/порт/SSL из формы загрузки.
- Строка 2 устанавливает пользовательское имя пользователя, но в остальном использует общие настройки.
- Строка 3 переопределяет сервер, порт и SSL.

Пример файла для скачивания доступен на странице импорта по кнопке **Download example CSV**.

### Форма загрузки {#upload-form}

| Поле | Назначение |
|---|---|
| **CSV file** | Файл для загрузки. |
| **IMAP server** | Общий хост для всех строк без переопределения `imap_server`. |
| **IMAP port** | Общий порт (по умолчанию 993). |
| **Use SSL** | Общий переключатель SSL (включен по умолчанию). |
| **Name prefix** | Префикс для автоматически генерируемых имен аккаунтов. По умолчанию: `IMAP`. |
| **Skip existing mailboxes** | Если включено, строки, адреса которых уже существуют в качестве IMAP-аккаунтов, будут пропущены (считаются как "пропущенные", а не ошибки). Если выключено, они будут считаться неудачными попыциями. |
| **Account enabled** | Должны ли созданные аккаунты быть включены для фоновой синхронизации. |
| **Delete After Days / Local Retention Days** | Необязательные настройки хранения, применяемые к каждому созданному аккаунту. См. [Retention Policies](RetentionPolicies.md). |

### Процесс обработки {#processing}

1. CSV-файл парсится, и каждая строка проверяется (формат email, наличие пароля, диапазон портов, значение SSL).
2. Дублирующиеся адреса электронной почты внутри файла удаляются (выигрывает первое вхождение).
3. Обнаруживаются существующие IMAP-аккаунты с тем же адресом электронной почты; в зависимости от переключателя **Skip existing** они либо пропускаются, либо помечаются как ошибки.
4. Все новые аккаунты вставляются единым пакетом (batch) в базу данных.
5. В лог доступа записывается сводка о выполнении операции.

Во время импорта проверка соединения с IMAP не выполняется — аккаунты сохраняются немедленно. Проблемы с аутентификацией проявятся только во время первой фоновой синхронизации. Это обеспечивает высокую скорость импорта даже для сотен почтовых ящиков.

### Страница результатов {#result-page}

После завершения импорта на странице результатов отображаются три таблицы:

- **Created** — email и имя каждого созданного аккаунта.
- **Skipped** — адреса, которые были дубликатами (внутри файла или уже существовали), когда включен параметр **Skip existing**.
- **Failed** — строки, которые не удалось обработать, с указанием номера строки и причины (отсутствует email, отсутствует пароль, неверный порт, нет IMта IMAP-сервера и т. д.).

В информационном баннере отображается сводка: *{created} создано, {skipped} пропущено, {failed} ошибок*.

### Лимиты {#limits}

Следующие лимиты можно настроить через `appsettings.json` / переменные окружения (см. [Setup Guide](Setup.md) → *CSV Import Settings*):

| Настройка | По умолчанию | Описание |
|---|---|---|
| `CsvImport__MaxRows` | 5000 | Максимальное количество строк, обрабатываемых за одну загрузку. |
| `CsvImport__MaxFileSizeBytes` | 10000000 (10 MB) | Максимальный размер загружаемого файла. |

### Примечание по безопасности {#security-note}

Пароли IMAP хранятся в базе данных так же, как и для индивидуально созданных IMAP-аккаунтов. Имейте в виду, что CSV-файл содержит все пароли почтовых ящиков в открытом виде — удалите его с клиентской машины после успешного импорта.

## Импорт Microsoft 365 Tenant {#microsoft-365-tenant-import}

Для Microsoft 365 (Exchange Online) массовый импорт не требует CSV-файла. Одна регистрация приложения Azure AD с соответствующими разрешениями Graph может получить доступ ко всем почтовым ящикам в тенанте, поэтому Mail Archiver может обнаруживать почтовые ящики автоматически.

См. специальное руководство: **[Microsoft 365 Tenant Mailbox Import](M365TenantImport.md)**.

# ☁️ Настройка личной учетной записи Microsoft (Outlook.com / M365 Family) {#personal-microsoft-account-outlookcom-m365-family-setup}

[← Назад к индексу документации](index.md)

## 📋 Обзор {#overview}

В данном руководстве объясняется, как архивировать электронные письма с **личной учетной записи Microsoft** (Outlook.com, Hotmail, live.com или Microsoft 365 Family) в Mail Archiver.

В отличие от корпоративных учетных записей Microsoft 365 (которые используют поток client-credentials — см. [Azure App Registration for M365](AZURE_APP_REGISTRATION_M365.md)), личные учетные записи используют **OAuth2 с потоком Device Code Flow (RFC 8628)**. Microsoft отозвала поддержку Basic Auth и паролей приложений для личных учетных записей, поэтому требуется OAuth2.

Mail Archiver поставляется с **заранее зарегистрированным общим Client ID**, поэтому большинству пользователей **не нужно** создавать собственную регистрацию приложения в Azure. Продвинутые пользователи по-прежнему могут зарегистрировать свое собственное приложение (см. Вариант B ниже).

## 🚀 Вариант A: Стандартная настройка (рекомендуется) {#option-a-standard-setup-recommended}

Используйте этот вариант, если в вашем экземпляре Mail Archiver настроен Client ID по умолчанию (стандарт для официальных Docker-образов). Доступ к Azure Portal не требуется.

### 🛠️ Предварительные требования {#prerequisites}

- Личная учетная запись Microsoft (Outlook.com, live.com или M365 Family)
- Устройство с браузером (смартфон, ноутбук или планшет) для завершения авторизации

### 📝 Шаги {#steps}

1. Войдите в приложение Mail Archiver.
2. Перейдите в **Mail Accounts** > **Create**.
3. Заполните следующие поля:
   - **Name**: Описательное имя для учетной записи (например, "Personal Outlook")
   - **Email Address**: Ваш личный адрес электронной почты Microsoft (например, `you@outlook.com`)
   - **Provider**: Выберите **Microsoft Personal**
4. Поля Client ID или Client Secret не отображаются — Mail Archiver автоматически использует встроенную регистрацию по умолчанию.
5. Нажмите **Create**.
6. Автоматически откроется страница авторизации через device-code. Отобразится короткий код (например, `ABCD-EFGH`) вместе со ссылкой на `https://microsoft.com/devicelogin` (или URL для проверки, указанный на экране).
7. На **любом устройстве** с браузером откройте этот URL и войдите в свою личную учетную запись Microsoft.
8. Введите код из шага 6.
9. Появится экран подтверждения, на котором будет указано, что **"Mail-Archiver"** запрашивает доступ к IMAP. Просмотрите и одобрите запрос.
10. Страница Mail Archiver автоматически обнаружит успех и перенаправит вас на страницу редактирования учетной записи.
11. Готово — синхронизация начинается автоматически в соответствии с настройками учетной записи.

> ⚠️ **Предупреждение о непроверенном издателе**: На экране подтверждения может появиться предупреждение о том, что "Mail-Archiver" является непроверенным издателем. Это ожидаемое поведение — проверка издателя требует наличия бизнес-идентификатора (аккаунта Microsoft Partner Network) и не требуется для работы потока. Приложение работает нормально и без этого.

## 🔧 Вариант B: Собственная регистрация приложения (для продвинутых пользователей) {#option-b-custom-app-registration-power-users}

Используйте этот вариант, если вы не хотите использовать общий Client ID по умолчанию (например, по соображениям соответствия требованиям безопасности или если вы хотите иметь полный контроль над регистрацией приложения).

### 🛠️ Предварительные требования {#prerequisites}

- Учетная запись Microsoft (личная или рабочая/учебная), имеющая доступ к Azure Portal
- Базовые навыки работы с порталом Azure/Entra

### 🚀 Создание регистрации приложения {#create-app-registration}

1. Перейдите в [Microsoft Entra Admin Center](https://entra.microsoft.com) или [Azure Portal](https://portal.azure.com).
2. Войдите в свою учетную запись Microsoft.
3. В левой навигационной панели выберите **App registrations** (в разделе Identity > Applications).
4. Нажмите **+ New registration**.
5. Заполните следующие данные:
   - **Name**: Введите описательное имя (например, "Mail Archiver MSA")
   - **Supported account types**: Выберите **Accounts in any organizational directory and personal Microsoft accounts**
     - Это многоарендный (multi-tenant) вариант, поддерживающий как личные, так и корпоративные учетные записи.
   - **Redirect URI**: Оставьте это поле пустым (не требуется для Device Code Flow).
6. Нажмите **Register**.
7. Запишите **Application (client) ID** со страницы **Overview**.

### 🔐 Включение потоков публичных клиентов (Public Client Flows) {#enable-public-client-flows}

1. В регистрации вашего приложения перейдите в раздел **Authentication** в левом меню.
2. Внизу найдите **Allow public client flows** и установите значение **Yes**.
3. Нажмите **Save**.

> ℹ️ Не нужно настраивать client secret, redirect URI или разрешения API вручную — Device Code Flow использует делегированные разрешения, которые запрашиваются во время выполнения через область доступа (scope) `IMAP.AccessAsUser.All`.

### 📧 Настройка Mail Archiver {#configure-mail-archiver}

Переопределение глобального значения по умолчанию (влияет на все MSA-аккаунты)

Установите Client ID в вашей переменной окружения:


```yaml
environment:
  - MsaOAuth__DefaultClientId=your-client-id-here
```

## 🔄 Обновление и отзыв токена {#token-refresh-revocation}

### Автоматическое обновление токена {#automatic-token-refresh}

После первоначальной авторизации Mail Archiver получает:
- **access token** (краткосрочный, ~1 час)
- **refresh token** (долгосрочный, используется для автоматического получения новых access токенов)

Mail Archiver автоматически обновляет access token перед каждым запуском синхронизации. Вам не нужно повторно проходить авторизацию, если только refresh token не истечет или не будет отозван.

### Отзыв доступа {#revoking-access}

Чтобы отозвать доступ Mail Archiver к вашей личной учетной записи Microsoft:

1. Перейдите на [https://account.live.com/consent/Manage](https://account.live.com/consent/Manage)
2. Войдите в свою личную учетную запись Microsoft.
3. Найдите **"Mail-Archiver"** (или имя вашего собственного приложения) в списке.
4. Нажмите **Remove**, чтобы отозвать доступ.

После отзыва доступа Mail Archiver больше не сможет получить доступ к учетной записи, пока вы не пройдете авторизацию заново.

## ⚠️ Важные примечания {#important-notes}
- **Общий Client ID**: При использовании Client ID по умолчанию все пользователи Mail Archiver на всех экземплярах используют одну и ту же регистрацию Azure App. Поддержка регистрации лежит на мейнтейнере Mail Archiver. Если Microsoft отключит общую регистрацию, всем пользователям потребуется перейти на собственную регистрацию (Вариант B), пока в новом релизе не будет обновлен Client ID.


- **Корпоративные учетные записи**: Провайдер Microsoft Personal использует конечную точку authority `/common` и поддерживает как личные, так и корпоративные (рабочие/учебные) учетные записи. Для корпоративных учетных записей, требующих доступа через client-credentials (только приложение, без входа пользователя), используйте вместо этого провайдер **M365**.

## 🔍 Устранение неполадок {#troubleshooting}

### Папки видны на outlook.com, но отсутствуют в Mail Archiver {#folders-visible-on-outlookcom-but-missing-in-mail-archiver}

**Симптом**: Некоторые папки существуют в почтовом ящике (видны на outlook.com или в Outlook), но они никогда не появляются в Mail Archiver — ни в списке папок на странице настроек аккаунта, ни во время синхронизации. Ошибки в логах нет.

**Причина (на стороне сервера)**: Папки, созданные **сторонними клиентами через EWS** — который настраивает учетные записи outlook.com как учетные записи Exchange, а не IMAP — могут иметь неверное свойство `PR_CONTAINER_CLASS` (например, `IPF.Imap` вместо `IPF.Note`). Outlook.com затем **полностью исключает эти папки из IMAP `LIST` ответа**, даже если они полностью видны в веб-интерфейсе. Это поведение на стороне Microsoft, а не ошибка Mail Archiver — аналогичный феномен задокументирован для Microsoft Graph API, где папки с контейнерным классом, отличным от `IPF.Note`, отсутствуют в списках `mailFolders`, пока свойство не будет исправлено:

Mail Archiver запрашивает список папок из трех источников (рекурсивный `LIST`, обход дочерних элементов каждой папки на каждом уровне и `LSUB`) и объединяет результаты. Если сервер не сообщает о папке ни через один из них, ни один IMAP-клиент не сможет её увидеть.

**Способ решения**: Один раз измените состояние затронутых папок через веб-интерфейс outlook.com, чтобы Microsoft исправил класс контейнера:

1. Откройте <https://outlook.com> и найдите отсутствующую папку.
2. Переименуйте её (любым временным именем), а затем переименуйте обратно — или создайте новую папку и переместите в неё письма.
3. Повторите это для каждой затронутой папки.
4. Запустите **Full Resync** учетной записи со страницы Account Details в Mail Archiver. Полная синхронизация необходима, так как инкрементальная синхронизация получает только те письма, которые новее даты последней синхронизации — письма в папках, которые никогда не были обнаружены, в противном случае останутся неархивированными.


*Данное руководство актуально на 2026 год. Microsoft регулярно обновляет свои сервисы и интерфейс, поэтому некоторые шаги могут отличаться. Для получения актуальной информации см. [документацию Microsoft identity platform](https://learn.microsoft.com/en-us/entra/identity-platform/).*

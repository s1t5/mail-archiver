# Архивация экземпляра Mailcow {#mailcow-instance-archiving}

[← Назад к индексу документации](index.md)

## Обзор {#overview}

Mail Archiver позволяет централизованно архивировать почтовые ящики экземпляра [Mailcow](https://mailcow.email), не собирая личные пароли владельцев ящиков.

Администратор один раз подключает экземпляр с помощью своего API key. Затем Mail Archiver выводит список почтовых ящиков и для каждого выбранного для архивации ящика создает **выделенный пароль приложения (app password)**, ограниченный `imap_access`. Этот пароль приложения используется существующим IMAP-провайдером для архивации ящика и может быть отозван в любое время.

Администраторы переходят к менеджеру экземпляров через **Add Account → Mailcow** или через меню действий аккаунта, который уже управляется через Mailcow. Менеджер доступен только администраторам, так как сохраненный API key может управлять учетными данными любого почтового ящика в экземпляре.

## Создание аккаунтов из Mailcow {#creating-accounts-from-mailcow}

В разделе **Mail Accounts → Add Account** администраторы могут выбрать **Mailcow** в качестве провайдера. После этого форма предложит список подключенных экземпляров и действие **Manage mailboxes**. Выбор ящиков в этом меню создает обычные IMAP-аккаунты архива с выделенными паролями приложений; отдельный аккаунт Mailcow не сохраняется. Если экземпляры еще не созданы, кнопка **Manage Mailcow instances** откроет менеджер экземпляров, где можно выполнить подключение.

## Привязка существующего аккаунта {#linking-an-existing-account}

В режиме редактирования IMAP-аккаунта администраторы могут переключить провайдера на **Mailcow** и выбрать экземпляр. Аккаунт сохраняет провайдера IMAP, но переходит под управление Mailcow: Mail Archiver создает выделенный пароль приложения, проверяет его через IMAP и заменяет сохраненный пароль аккаунта. После этого аккаунт появится в списке с пометкой Mailcow action.

Чтобы выйти из управления Mailcow, выберите другого провайдера и сохраните изменения. Пароль приложения будет отозван, а локальный пароль очищен. При переключении обратно на IMAP введите новый IMAP-пароль; при переключении на Microsoft 365 или аккаунт только для импорта будут использованы соответствующие учетные данные. Не-администраторы по-прежнему могут редактировать настройки аккаунта, не связанные с учетными данными, но не могут привязывать или отвязывать его от Mailcow.

## Предварительные условия {#prerequisites}

### Шифрование учетных данных должно быть включено {#credential-encryption-must-be-enabled}

Mail Archiver сохраняет Mailcow API key и каждый сгенерированный пароль приложения в зашифрованном виде, используя существующую функцию шифрования учетных данных. Установите

```
Security__CredentialEncryptionKey=<base64-encoded 32-byte key>
```

перед подключением экземпляра. Создание экземпляра и активация почтовых ящиков будут отклонены, если шифрование отключено, поэтому учетные данные никогда не могут быть записаны в виде открытого текста через эту функцию. Храните ключ вне базы данных и включите его в свой защищенный бэкап — без него сохраненные пароли приложений невозможно будет расшифровать, а почтовые ящики нельзя будет подготовить. Подробности см. в разделе [Setup](Setup.md#-security-settings).

### Доступ к Mailcow API {#mailcow-api-access}

Создайте API key в Mailcow в разделе **Configuration → Access → API**. Ключ должен иметь разрешения на:

- просмотр списка почтовых ящиков (`get/mailbox/all`),
- просмотр, создание и удаление паролей приложений (`get/app-passwd/all`, `add/app-passwd`,
  `delete/app-passwd`).

Ограничьте доступ к API IP-адресом хоста Mail Archiver в настройках API Mailcow. Для работы эндпоинта app-password в Mailcow должна быть включена функция **App Passwords** для данного экземпляра.

### Сетевой доступ {#network-access}

- **HTTPS** к источнику Mailcow (например, `https://mail.example.com`).
- **IMAP over TLS** к IMAP-хосту, обычно порт `993`. IMAP без шифрования не поддерживается для подготовки ящиков.

## Пошаговое использование {#step-by-step-usage}

### Подключение экземпляра {#connecting-an-instance}

1. Войдите в Mail Archiver как администратор.
2. Откройте **Mail Accounts** и нажмите **Mailcow instances**.
3. Нажмите **Connect Mailcow instance**.
4. Введите данные подключения:
   - **Account name** — отображаемое имя экземпляра в Mail Archiver.
   - **Mailcow URL** — только HTTPS origin, например `https://mail.example.com`.
     Пути, строки запроса и встроенные учетные данные отклоняются.
   - **API key** — ключ, созданный в Mailcow.
   - **IMAP host** — имя хоста, используемое для архивации, например `mail.example.com`.
     Введите только имя хоста, без схемы или порта.
   - **IMAP TLS port** — по умолчанию `993`.
5. Нажмите **Connect**. Mail Archiver проверяет API key, запрашивая список почтовых ящиков, прежде чем сохранить экземпляр. В случае успеха откроется выбор ящиков.

API key хранится в зашифрованном виде и никогда не выводится обратно в форму или в сообщения об ошибках. HTTP-перенаправления отключены для API-вызовов, чтобы ключ не мог быть перенаправлен на другой origin.

### Активация почтовых ящиков {#activating-mailboxes}

1. На странице почтовых ящиков при необходимости отфильтруйте список с помощью поля поиска. Фильтр ищет совпадения по адресу и отображаемому имени и нечувствителен к регистру.
2. Выберите ящики для архивации. Действия **Select all** и **Clear selection** применяются только к текущим видимым (отфильтрованным) ящикам, поэтому фильтрация — безопасный способ выбрать подмножество.
3. Нажмите **Activate archiving**.

Для каждого выбранного ящика Mail Archiver:

1. повторно проверяет адрес по текущему списку ящиков Mailcow и игнорирует отключенные ящики,
2. создает архивный аккаунт с именем `{instance name} – {mailbox display name}`,
3. генерирует случайный пароль приложения с именем `MailArchiver-<unique id>`, ограниченный `imap_access`,
4. проверяет учетные данные с помощью IMAP login через TLS,
5. и только после этого включает синхронизацию.

Если проверка IMAP не удалась, аккаунт остается отключенным, и попытку можно повторить.

### Статусы почтовых ящиков {#mailbox-status-badges}

На странице выбора каждый ящик помечен статусом, чтобы было понятно, почему чекбокс доступен или нет:

| Badge | Значение | Выбираемый |
| --- | --- | --- |
| **Available** | Есть в Mailcow, еще не подготовлен | yes |
| **Active** | Подготовлен и синхронизируется | no |
| **Pending** | Подготовка начата, но не завершена (можно повторить) | yes |
| **Revoked** | Пароль приложения отозван; можно активировать снова | yes |
| **Existing** | Независимый IMAP-аккаунт с этим адресом уже существует | no |
| **Disabled** | Ящик отключен в Mailcow | no |

### Повторная попытка для ящика в статусе Pending {#retrying-a-pending-mailbox}

Сгенерированные учетные данные и уникальное имя пароля приложения сохраняются **до** вызова Mailcow API. Если запрос завершился неопределенно — например, по таймауту после создания пароля приложения — ящик остается в статусе **Pending**. Обновите страницу и выберите его снова: Mail Archiver сначала ищет существующее имя пароля и создает новый пароль приложения только в том случае, если его нет. Повторные попытки не приводят к дублированию учетных данных.

Подготовка и отзыв для одного экземпляра сериализованы с использованием advisory locks PostgreSQL, поэтому две параллельные операции не могут подготовить один и тот же ящик дважды.

### Отзыв доступа {#revoking-access}

Нажмите **Revoke app password** рядом с ящиком. Это:

- отключает будущую синхронизацию,
- удаляет управляемый пароль приложения в Mailcow,
- и очищает локальный пароль.

**Архивные письма сохраняются.** Удаляется только управляемый пароль приложения — другие пароли приложений, принадлежащие этому ящику, не затрагиваются. Уже запущенные операции синхронизации могут завершиться, используя существующее соединение.

Если удаленный запрос не удался, аккаунт остается отключенным, и отзыв можно повторить.

Удаление архивного аккаунта в **Mail Accounts** не удаляет удаленные учетные данные незаметно. Привязка остается в списке **Remaining app passwords** на странице экземпляра, чтобы ее можно было отозвать явно.

### Редактирование экземпляра {#editing-an-instance}

Откройте **Mailcow instances** и нажмите **Edit**. Поле API key всегда пустое — сохраненный ключ никогда не отображается. Оставьте его пустым, чтобы сохранить текущий ключ, или введите новый, чтобы заменить его. Измененные данные подключения проверяются в Mailcow перед сохранением.

### Удаление экземпляра {#deleting-an-instance}

Откройте **Mailcow instances** и нажмите **Delete**.

Удаление экземпляра удаляет его зашифрованный API key и привязки к ящикам. **Архивные аккаунты и их архивные письма сохраняются**, но аккаунты переводятся в состояние отключенных.

Удаление будет **отклонено, если какой-либо управляемый пароль приложения все еще активен** в Mailcow: удаление экземпляра удалит API key, необходимый для его отзыва. Сначала отзовите все управляемые пароли приложений на странице почтовых ящиков.

## Журналирование аудита {#audit-logging}

Каждая административная операция записывается в лог доступа с указанием совершившего ее пользователя:

- подключение экземпляра,
- обновление экземпляра,
- удаление экземпляра,
- активация почтовых ящиков (с указанием количества подготовленных и неудачных),
- отзыв пароля приложения.

## Лимит почтовых ящиков {#mailbox-limit}

Один запуск активации может подготовить не более `Mailcow__MaxSelectedMailboxes` ящиков (по умолчанию `1000`). Это защищает от случайной массовой подготовки и чрезмерной нагрузки на Mailcow API и IMAP. Для более крупных экземпляров запустите операцию несколько раз.

Каждый почтовый ящик требует нескольких циклов запросов к API плюс проверку IMAP, и они обрабатываются последовательно. Подготовка сотен ящиков за один запрос может привести к превышению таймаутов обратного прокси или браузера; разделите выборку на пакеты.

## Заметки по безопасности {#security-notes}

- API key остается на стороне сервера. Он отправляется в заголовке `X-API-Key`, маскируется в логах и никогда не возвращается в браузер.
- Ответы Mailcow на запросы паролей приложений могут содержать пароли в открытом виде в полях `log`. Mail Archiver намеренно не логирует тела ответов и не выводит ошибки API в браузер; ошибки сообщаются в виде локализованных сообщений.
- Ответ HTTP 200 не всегда означает успех: для изменений требуются `type: success` от Mailcow для каждого результата.
- Разрешение IMAP не является по своей сути «только для чтения». У подготовленных аккаунтов нет настроенной политики удаления на стороне сервера, и администраторы сохраняют контроль над настройками аккаунта. Эта функция архивирует сообщения, а не конфигурацию или бэкапы Mailcow.

### Хосты и частные сети {#hostnames-and-private-networks}

URL Mailcow и IMAP-хост вводятся администратором и могут указывать на частное адресное пространство. Это сделано намеренно и поддерживается: Mail Archiver обычно развертывается рядом с почтовым сервером, поэтому `mail.example.lan`, `192.168.10.20` или `10.0.0.5` являются нормальными значениями. **Ни один частный, loopback или link-local адрес не блокируется.**

Границей доверия является роль администратора, а не сетевой адрес. `Mail Accounts` доступен самообслуживающим пользователям, которые могут уже настраивать произвольный IMAP-сервер для своих аккаунтов; раздел Mailcow ограничен администраторами, а у администратора уже есть неограниченный доступ ко всем архивным аккаунтам в установке. Таким образом, ограничение IMAP-хоста не создаст новой границы привилегий, но нарушит работу при развертывании on-premise.

Все же действуют два ограничения:

- URL Mailcow должен быть чистым HTTPS origin. Пути, строки запроса, информация о пользователе и перенаправления отклоняются, поэтому API key не может быть перенаправлен на другой origin.
- IMAP-хост должен быть именем хоста без схемы или порта, и подготовка всегда выполняется через TLS (`SslOnConnect`).

Если вам нужно ограничить хосты, до которых может достучаться Mail Archiver, делайте это на сетевом уровне — правилами egress firewall или DNS-политикой для контейнера — а не полагайтесь на валидацию ввода в приложении.

## Устранение неполадок {#troubleshooting}

| Симптом | Причина и решение |
| --- | --- |
| *Encryption required* при подключении или активации | `Security__CredentialEncryptionKey` не установлен или недействителен. Настройте 32-байтовый ключ в кодировке base64 и перезапустите. |
| *HTTPS origin required* | URL содержит путь, строку запроса или встроенные учетные данные. Введите чистый origin, например `https://mail.example.com`. |
| *IMAP host invalid* | IMAP-хост должен быть именем хоста без схемы или порта. |
| *Instance already connected* | Существует другой экземпляр с тем же URL. Вместо этого отредактируйте существующий экземпляр. |
| *API request failed (401/403)* | API key не имеет необходимых разрешений или ограничение по IP не включает хост Mail Archiver. |
| *API request rejected* | Mailcow вернул строку `error`/`danger`/`warning`. Проверьте логи Mailcow; Mail Archiver не передает тела ответов. |
| *IMAP verification failed* | Неверный IMAP-хост или порт, недоверенный сертификат или функция паролей приложений отключена в Mailcow. |
| *IMAP account exists* | Независимый IMAP-аккаунт уже архивирует этот адрес. Используйте этот аккаунт вместо создания второго архива. |
| *Revoke previous password* | Архивный аккаунт для этого ящика был удален. Сначала отзовите оставшийся пароль приложения, затем активируйте снова. |
| Ящик остается в статусе **Pending** | Таймаут Mailcow API. Обновите страницу и активируйте ящик снова; дубликат пароля приложения не будет создан. |
| Удаление отклонено | Управляемые пароли приложений все еще активны. Сначала отзовите их на странице почтового ящика. |

## Используемые эндпоинты API {#api-endpoints-used}

- `GET /api/v1/get/mailbox/all`
- `GET /api/v1/get/app-passwd/all/{mailbox}`
- `POST /api/v1/add/app-passwd`
- `POST /api/v1/delete/app-passwd`

## Изменения в базе данных {#database-changes}

Миграция добавляет только таблицы `MailcowInstances` и `MailcowMailboxes` вместе с их индексами и внешними ключами. Существующие таблицы почтовых ящиков и архивные данные сохраняются. Удаление архивного аккаунта устанавливает `MailAccountId` привязки в `NULL`, чтобы удаленный пароль можно было отозвать позже.

# MCP Server (Model Context Protocol) {#mcp-server-model-context-protocol}

Mail Archiver поставляется с опциональным **MCP (Model Context Protocol) server**, который
предоставляет доступ к архивированной почте AI-агентам через транспорт Streamable HTTP. Он
зеркально отражает [REST API](API.md) в режиме «только для чтения»: те же данные, та же модель
прав доступа для каждого пользователя, то же ведение логов доступа — просто упакованные в виде инструментов MCP вместо конечных точек REST, чтобы LLM-агент мог обнаруживать и вызывать их напрямую.

Цель состоит в том, чтобы позволить AI-агенту читать архивированную почту, **никогда не раскрывая
учетные данные почтового ящика и не взаимодействуя напрямую с почтовым провайдером.** Ограниченный API-ключ пользователя — это возможность *читать архив*, а не учетные данные для того, чтобы *стать почтовым ящиком* — он наследует только права доступа к почтовому ящику своего владельца, не предоставляет прав на запись и может быть мгновенно отозван без изменения настроек основного почтового аккаунта.

> ⚠️ **MCP server по умолчанию отключен.** Его необходимо явно включить в
> конфигурации (см. [Enabling the MCP server](#enabling-the-mcp-server)). Когда
> он отключен, эндпоинт `/mcp` возвращает `404 Not Found`.

MCP server **по своей конструкции предназначен только для чтения**: он предоставляет инструменты для вывода списка аккаунтов,
вывода списка папок, поиска сообщений, чтения сообщения и скачивания вложения. Он
никогда не создает, не изменяет и не удаляет данные.

## Включение MCP сервера {#enabling-the-mcp-server}

MCP сервер настраивается в разделе `Mcp` в `appsettings.json` (или через соответствующие переменные окружения, например, `Mcp__Enabled=true`):

```json
"Mcp": {
  "Enabled": false,
  "AllowAttachmentDownloads": true,
  "DefaultPageSize": 20,
  "MaxResults": 100,
  "MaxAttachmentBytes": 10000000,
  "AllowMessageDownloads": true,
  "MaxMessageBytes": 10000000,
  "RateLimitPerMinute": 120
}
```

| Setting | Default | Description |
| --- | --- | --- |
| `Enabled` | `false` | Главный переключатель. Когда `false`, эндпоинт `/mcp` возвращает `404`. |
| `AllowAttachmentDownloads` | `true` | Когда `false`, `get_attachment` возвращает ошибку вместо байтов вложения. Метаданные о вложениях по-прежнему возвращаются через `get_email`. |
| `DefaultPageSize` | `20` | Размер страницы, используемый `search_emails`, если вызывающая сторона опускает `pageSize`. |
| `MaxResults` | `100` | Верхний предел размера страницы `search_emails`; большие значения ограничиваются. |
| `MaxAttachmentBytes` | `10000000` | Максимальный размер вложения (в байтах), который `get_attachment` будет возвращать inline в формате base64; вложения большего размера отклоняются. |
| `AllowMessageDownloads` | `true` | Когда `false`, `get_email_eml` и `get_email_raw` возвращают ошибку вместо сообщения. Полное сообщение содержит свои вложения, поэтому **оба** этот переключатель и `AllowAttachmentDownloads` должны быть `true`; отключение любого из них отключает оба инструмента. |
| `MaxMessageBytes` | `10000000` | Максимальный размер сообщения (в байтах), который `get_email_eml` и `get_email_raw` будут возвращать inline; сообщения большего размера отклоняются. |
| `RateLimitPerMinute` | `120` | Бюджет запросов с фиксированным окном на один API key в минуту (см. [Rate limiting](#rate-limiting)). |

## Authentication {#authentication}

MCP-сервер проходит аутентификацию с использованием **тех же API-ключей для каждого пользователя, что и REST API**, которые передаются в качестве bearer-токена:

```
Authorization: Bearer ma_<43 url-safe base64 characters>
```

API-ключи создаются и управляются в веб-интерфейсе в разделе **API Keys**. Ключ наследует ровно те же разрешения, которыми обладает владеющий им пользователь (администратор видит все аккаунты; пользователь с ограниченными правами видит только назначенные ему аккаунты). Ключи могут быть отозваны или просрочены независимо от основных почтовых аккаунтов. См. [раздел REST API authentication](API.md#authentication) для получения полной информации о жизненном цикле ключей и модели разрешений — ключи MCP не являются отдельным хранилищем учетных данных.

Если MCP-сервер отключен или не предоставлен корректный/отсутствующий bearer-токен, эндпоинт возвращает `404` / `401` соответственно (перенаправление на страницу входа не выполняется).

## Транспорт и эндпоинт {#transport-and-endpoint}

MCP сервер использует транспорт **Streamable HTTP** и смонтирован по адресу:

```
POST /mcp
```

Он работает в **stateless** режиме (один JSON-RPC запрос на один HTTP запрос), что является рекомендуемым режимом для серверов, которым не требуются запросы от сервера к клиенту, такие как sampling или elicitation. Инструменты обнаруживаются через стандартный запрос MCP `tools/list` и вызываются через `tools/call`.

## Tools {#tools}

### list_accounts {#list_accounts}

Выводит список почтовых аккаунтов, к которым текущий API key имеет доступ. Возвращает
`id`, `name`, `emailAddress`, `provider`, `isEnabled` и `lastSync`.

**Параметры:** отсутствуют.

**Результат:** массив объектов аккаунтов. Используйте возвращаемый `id` с `list_folders`
и `search_emails`.

### list_folders {#list_folders}

Выводит дерево папок одного почтового аккаунта с количеством писем в каждой папке.

**Параметры:**

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `accountId` | integer | yes | ID почтового аккаунта (из `list_accounts`). |

**Результат:** массив объектов папок, каждый из которых содержит `name`, `fullPath`, `totalCount`,
`level` и рекурсивный `children`. Возвращает пустой список, если аккаунт не
существует или ключ не авторизован для него.

### search_emails {#search_emails}

Выполняет поиск по архиву писем с использованием полнотекстового запроса, диапазона дат, аккаунта, папки и направления.

**Параметры:**

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `q` | string | no | Полнотекстовый поисковый запрос (тема, тело письма, от/кому). |
| `from` | string (ISO-8601) | no | Фильтр даты/времени UTC (отправлено в или после). |
| `to` | string (ISO-8601) | no | Фильтр даты/времени UTC (отправлено в или до). |
| `accountId` | integer | no | Ограничить одним ID почтового аккаунта. |
| `folder` | string | no | Ограничить полным путем к одной папке (например, `INBOX`). |
| `direction` | string | no | `incoming` или `outgoing`. |
| `page` | integer | no | Номер страницы (начиная с 1, по умолчанию `1`). |
| `pageSize` | integer | no | Размер страницы; ограничен значением `[1, MaxResults]`. `0` использует `DefaultPageSize`. |
| `sortBy` | string | no | `sentdate` (по умолчанию), `receiveddate`, `subject`, `from`, `to`. |
| `sortOrder` | string | no | `asc` или `desc` (по умолчанию `desc`). |

**Результат:** объект с пагинацией, содержащий `items` (массив кратких сводок писем), `page`, `pageSize`, `totalItems`, `totalPages`. Каждая сводка содержит `id`, `accountId`, `subject`, `from`, `to`, `sentDate`, `isOutgoing`, `hasAttachments` и `folderName`. Передайте возвращенный `id` в `get_email` для получения полного текста письма и списка вложений.

### get_email {#get_email}

Извлекает полное содержимое одного архивного письма.

**Параметры:**

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | integer | yes | ID архивного письма (из `search_emails`). |

**Результат:** один объект письма со всеми полями сводки, а также `cc`, `bcc`,
`receivedDate`, `messageId`, `textBody`, `htmlBody` и `attachments` (массив
`{ id, fileName, contentType, size }`) и `hasRawMessage` (может ли
`get_email_raw` вернуть оригинал). Возвращает `null`, если письмо не
существует или ключ не авторизован для данного аккаунта.

### get_attachment {#get_attachment}

Загружает одно вложение электронной почты в виде base64-блоба.

**Параметры:**

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | integer | yes | ID архивированного письма, которому принадлежит вложение. |
| `attachmentId` | integer | yes | ID вложения (из `attachments` инструмента `get_email`). |

**Результат:** объект с `id`, `emailId`, `fileName`, `contentType`, `size`
и `base64Data` (необработанные байты вложения, закодированные в base64). Инструмент возвращает
ошибку, если `Mcp:AllowAttachmentDownloads=false`, если вложение превышает
`Mcp:MaxAttachmentBytes`, или если ключ не авторизован для учетной записи
этой электронной почты.

### get_email_eml {#get_email_eml}

Возвращает электронное письмо в виде полного сообщения RFC 5322 (`.eml`), воссозданного из
архивированных полей: сохраненных заголовков (`Received`, `Authentication-Results`,
`X-Spam-*`, …), тел и вложений. Работает для каждого архивированного письма, но
результат не является байт-в-байт идентичным полученному, поэтому подписи DKIM не пройдут проверку — для этого используйте [`get_email_raw`](#get_email_raw). Зеркальное отражение `GET /api/v1/emails/{id}/eml`.

**Параметры:**

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | integer | yes | ID архивированного письма (из `search_emails`). |

**Результат:** объект с `emailId`, `kind` (`eml`), `source` (`null`),
`sha256`, `size`, `encoding` и `content`. `content` — это текст сообщения, когда
`encoding` равен `utf-8`, и сообщение в кодировке base64, когда `encoding` равен
`base64` (сообщения, которые не являются валидным UTF-8, чтобы ни один байт не был изменен). Инструмент возвращает ошибку, если `Mcp:AllowMessageDownloads=false`, если сообщение
превышает `Mcp:MaxMessageBytes`, или если ключ не авторизован для
аккаунта электронной почты.

### get_email_raw {#get_email_raw}

Возвращает исходное сообщение именно в том виде, в котором оно было получено, для анализа спама, проверок DKIM/SPF/ARC или криминалистической экспертизы. Доступно только в том случае, если оригинал был сохранен в момент архивации (`RawMessages:Enabled`, см.
[Original Message Storage Settings](Setup.md#-original-message-storage-settings));
`get_email` сообщает о нем как о `hasRawMessage`. Зеркально отражает
`GET /api/v1/emails/{id}/raw`.

**Параметры:**

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | integer | yes | ID архивированного письма (из `search_emails`). |

**Результат:** тот же объект, что и `get_email_eml`, с `kind` `raw`, где `source` установлен
в соответствии с тем, как был захвачен оригинал (`imap`, `graph`, `eml-file` — точные копии —
или `serialized`, переписанный парсером с нормализацией окончаний строк до CRLF)
и `sha256` контрольная сумма, записанная в момент архивации. Возвращает те же ошибки, что и
`get_email_eml`, а также ошибку, если для письма не сохранен оригинал.

Байты считываются оттуда, где они были сохранены — из базы данных или из файла,
в зависимости от `RawMessages:Storage` в момент архивации (см.
[Storage backend](RawMessages.md#storage-backend)). При
`RawMessages:FileSystem:VerifyChecksumOnRead` (по умолчанию `true`) файл
повторно хешируется перед возвратом; сообщение, содержимое которого больше не соответствует
записанной контрольной сумме, отклоняется с ошибкой, а не возвращается.

## Rate limiting {#rate-limiting}

MCP-сервер имеет собственную политику ограничения частоты запросов с фиксированным окном (`"Mcp"`), разделенную по несекретному префиксу API-ключа (первые 11 символов токена `ma_...`), с переходом на IP-адрес клиента, если bearer-токен отсутствует. Бюджет настраивается через `Mcp:RateLimitPerMinute` (по умолчанию `120` в минуту). При превышении лимита эндпоинт возвращает `429 Too Many Requests` с заголовком `Retry-After`. Это работает независимо от политики ограничения частоты запросов REST API.

## Логирование доступа {#access-logging}

Каждый вызов инструмента регистрируется через тот же `IAccessLogService`, что и REST API,
с указанием имени пользователя-владельца и соответствующего типа доступа (`Search`, `Open`,
`Download`). Таким образом, активность MCP видна на странице **Logs** наряду
с активностью REST API и web-UI, обеспечивая единый аудиторский след.

## Подключение агента {#connecting-an-agent}

MCP-сервер использует стандартный транспорт MCP Streamable HTTP, поэтому к нему может подключиться любой MCP-клиент, поддерживающий HTTP. URL-адрес представляет собой базовый URL-адрес приложения плюс `/mcp`, например `http://localhost:5179/mcp`, а API-ключ передается через заголовок `Authorization: Bearer ma_...`.

Для агентов, настроенных через стандартный JSON MCP-клиента, запись выглядит следующим образом:

```json
{
  "mcpServers": {
    "mail-archiver": {
      "url": "https://archive.example.com/mcp",
      "headers": {
        "Authorization": "Bearer ma_<your-api-key>"
      }
    }
  }
}
```

## Руководство по безопасности при открытом доступе из интернета {#security-guidance-for-internet-exposure}

MCP-сервер спроектирован таким образом, что при использовании настроек по умолчанию и описанных ниже мер по усилению защиты, архивная почта не может покинуть систему без валидного API-ключа пользователя, который был явно выдан учетной записи. Нижеуказанные пункты являются **обязательными для прочтения перед открытием доступа к `/mcp` из интернета**.

### Обязательные требования (предотвращение эксплуатации / эксфильтрации данных) {#mandatory-block-exploitation-data-exfiltration}

1. **Только HTTPS.** Завершайте TLS на границе сети (обратный прокси). API-ключ типа bearer, передаваемый через обычный HTTP, может быть перехвачен и использован повторно.
2. **Держите `Mcp:Enabled=false` выключенным, если вы его фактически не используете.** Когда функция отключена, `/mcp` возвращает `404`, и никакой путь выполнения кода не будет достижим; это безопасное значение по умолчанию и безопасное состояние для развертываний, которым не требуется доступ ИИ-агентов.
3. **Ограничение скорости (rate limiting) применяется к эндпоинту.** Политика `"Mcp"` (`Mcp:RateLimitPerMinute`, по умолчанию `120`) применяется к сопоставленному эндпоинту `/mcp`. Она разделяется по несекретному префиксу API-ключа (первые 11 символов токена `ma_...`) или по IP-адресу клиента, если bearer-токен отсутствует. **Снижайте `RateLimitPerMinute`** для доступа из интернета (например, `30`–`60`) — вызовы инструментов MCP тяжелее, чем REST-вызовы, и эндпоинту не следует оставлять высокий бюджет, когда к нему могут обращаться ненадежные клиенты.
4. **К обратным прокси `X-Forwarded-For` нужно относиться с осторожностью.** Ограничитель скорости переключается на `RemoteIpAddress`, который при использовании прокси является IP-адресом прокси, если в `UseForwardedHeaders` не передан реальный IP-адрес клиента. Убедитесь, что ваш прокси правильно устанавливает `X-Forwarded-For` и что только ваш прокси может это делать; в противном случае злоумышленник может подменить раздел ограничения скорости.
5. **Не размещайте `/mcp` за кэшем CDN.** Ответы MCP являются JSON-RPC на каждый запрос и никогда не должны кэшироваться — кэширование нарушит протокол и приведет к утечке результатов одного пользователя другому. Пометьте `/mcp` как некэшируемый на границе сети (`Cache-Control: no-store`).

### Гигиена API-ключей (предотвращение несанкционированного доступа) {#api-key-hygiene-block-unauthorized-access}

6. **Выдавайте выделенные, краткосрочные ключи для MCP-агентов.** Один ключ `ma_...` действителен как для `/api`, так и для `/mcp`; на данный момент разделения по протоколам не существует. Поэтому:
   - Создавайте **отдельный ключ для каждого агента** (не используйте ключ скрипта отчетности для внешнего LLM-агента).
   - Всегда устанавливайте короткий срок действия `ExpiresAt` и ротируйте его; немедленно отзывайте ключ при выводе агента из эксплуатации.
   - Предпочитайте ключи, принадлежащие **ограниченному (не администратору) пользователю**, чьими единственными назначенными учетными записями являются те, что необходимы агенту. Ключ администратора дает доступ ко *всем* почтовым аккаунтам; ограниченный ключ минимизирует радиус поражения.
7. **Относитесь к API-ключу как к паролю.** Это учетные данные типа bearer. Никогда не встраивайте его в клиентский код, никогда не логируйте его и не фиксируйте в репозитории. Храните его в защищенном хранилище MCP-клиента и ротируйте при подозрении на компрометацию.
8. **Проводите аудит на странице Logs.** Каждый вызов инструмента записывается в `AccessLogs` (`Search`, `Open`, `Download`) под соответствующим пользователем. Периодически проверяйте активность MCP на предмет неожиданных паттернов (всплески объема, чтение во внерабочее время, массовые загрузки).

### Модель доверия к возвращаемым данным (предотвращение вреда для потребителя) {#trust-model-for-returned-data-block-downstream-harm}

9. **Тела писем и вложения являются недоверенным контентом**, точно так же, как они были, когда поступили в почтовый ящик. Они могут содержать вредоносное ПО, фишинговые ссылки или активный HTML/JavaScript.
   - `get_email` возвращает `htmlBody` в **сыром и несанированном виде**. **Не** отображайте его человеку без санитарной обработки (DOMPurify / `HtmlSanitizer` / песочница). Отображение сырого архивированного HTML является вектором хранения XSS (stored-XSS).
   - `get_attachment` возвращает сырые байты с оригинальным `contentType`. **Не** открывайте и **не** выполняйте вложения автоматически; относитесь к полю `contentType` как к недоверенным метаданным, а не как к безопасной инструкции.
   - `get_email_eml` и `get_email_raw` возвращают полное сообщение, включая каждое вложение. Те же правила применяются к каждой из его частей.
10. **Не позволяйте агенту выполнять действия записи на основе содержимого почты без подтверждения.** Вредоносное письмо может содержать текст для prompt-инъекции, направленный на потребляющую LLM. Обеспечьте соблюдение разрешений и подтверждений в собственной логике агента — системный промпт не является границей безопасности.

### Рекомендации по эшелонированной защите {#defense-in-depth-recommendations}

11. **Ограничивайте `/mcp` на сетевом уровне**, когда это возможно (например, разрешите только IP-адрес хоста агента / диапазон VPN на обратном прокси), в дополнение к аутентификации по API-ключу. Это самый эффективный метод контроля при открытом доступе из интернета.
12. **Снизьте `Mcp:AllowAttachmentDownloads` до `false`**, если вашим агентам не требуются байты вложений — эксфильтрация вложений является путем передачи данных с самым большим объемом. Метаданные (имя файла, тип контента, размер) по-прежнему возвращаются через `get_email`.
13. **Снизьте `Mcp:MaxAttachmentBytes`** до минимального значения, которое действительно требуется вашим агентам (по умолчанию `10000000` ≈ 10 МБ). Это ограничивает максимальный размер одного ответа, который API-ключ может получить за один запрос. То же самое касается `Mcp:MaxMessageBytes`, или установите `Mcp:AllowMessageDownloads` равным `false`, если агентам не требуются полные сообщения.
14. **Снизьте `Mcp:MaxResults` и `Mcp:DefaultPageSize`**, чтобы ограничить максимальный результат поиска, который API-ключ может получить за один запрос (по умолчанию `100` / `20`).
15. **Оперативно отслеживайте `AccessLogs` и отказы по ограничению скорости** (`429`). Внезапный всплеск от одного префикса ключа является сигналом к отзыву этого ключа.

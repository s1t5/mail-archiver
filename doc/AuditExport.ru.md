# 📤 Экспорт аудиторских данных {#audit-data-export}

[← Назад к индексу документации](index.md)

## 📋 Обзор {#overview}

Экспорт аудиторских данных создает пакеты массовых табличных данных (ZIP с `INDEX.XML` + таблицы CSV + индексный DTD) из существующего архива. Эти пакеты соответствуют установленной структуре индекса для передачи носителей данных и могут быть напрямую импортированы распространенными внешними инструментами аудита и анализа, поддерживающими этот формат индекса.

Эта функция доступна в виде **отдельной страницы, достижимой со страницы Logs**, и ограничена для пользователей с правами администратора. Каждый запуск экспорта записывается в лог доступа, поэтому история экспорта является защищенной от изменений (revision-safe).

## 🧭 Доступ {#access}

1. Войдите в систему как администратор
2. Откройте страницу **Logs**
3. Нажмите кнопку **Audit Data Export** в правом верхнем углу

Пользователи без прав администратора не видят эту кнопку и не могут вызывать никакие эндпоинты экспорта (сервер отклоняет их запросы).

## 📦 Структура пакета экспорта {#export-package-structure}

Сгенерированный ZIP-файл называется `audit-export-<timestamp>.zip` и содержит:

| Файл | Содержимое |
|---|---|
| `INDEX.XML` | Файл индекса, описывающий поставщика данных, носитель и все определения таблиц/столбцов |
| `index.dtd` | DTD, на который ссылается файл индекса; необходим инструментам импорта для валидации |
| `emails.csv` | Одна строка на каждое архивированное письмо за выбранный период/почтовый ящик |
| `attachments.csv` | Опционально; одна строка на каждое вложение экспортируемых писем |

### Таблица `emails.csv` {#table-emailscsv}

Столбцы (без строки заголовка; имена столбцов берутся из `INDEX.XML`, как обычно для этого формата):

| Столбец | Описание |
|---|---|
| Id | Внутренний ID письма (числовой) |
| MessageId | Заголовок Email Message-ID |
| SentDate | Дата отправки, ISO 8601 UTC (`yyyy-MM-ddTHH:mm:ssZ`) |
| ReceivedDate | Дата получения, ISO 8601 UTC |
| IsOutgoing | `1` = исходящее, `0` = входящее |
| From | Отправитель |
| To | Получатели |
| Cc | Получатели в копии (CC) |
| Bcc | Получатели в скрытой копии (BCC) |
| Subject | Тема |
| FolderName | Папка, в которой архивировано письмо |
| HasAttachments | `1` = с вложениями, `0` = без вложений |
| AttachmentCount | Количество вложений (числовое) |
| AccountEmail | Адрес электронной почты архивируемого почтового ящика |

### Таблица `attachments.csv` {#table-attachmentscsv}

| Столбец | Описание |
|---|---|
| EmailId | Внутренний ID письма, которому принадлежит вложение (ключ соединения с `emails.csv`) |
| FileName | Имя файла вложения |
| ContentType | MIME-тип |
| Size | Размер в байтах (числовой) |
| Sha256 | Хеш SHA-256 содержимого (из хранилища вложений по адресу содержимого) |

### Конвенции CSV {#csv-conventions}

- Кодировка: UTF-8 **без** BOM (объявлена как `UTF8` в `INDEX.XML`)
- Разделитель столбцов: `;`
- Экранирование текста: `"` (удваивается для экранирования)
- Разделитель записей: `\n` (явно объявлен в `INDEX.XML`)
- Даты: ISO 8601, время преобразовано из настроенного часового пояса отображения в UTC
- Без строки заголовка; без локализованных чисел (числовые столбцы содержат обычные целые числа)

## 🖥️ Использование страницы экспорта {#using-the-export-page}

### Поля формы {#form-fields}

1. **From / To date** — Период для экспорта (обязательно, максимальный охват настраивается, по умолчанию 10 лет)
2. **Mailbox** — Ограничить экспорт одним почтовым ящиком или экспортировать все почтовые ящики
3. **Attachment metadata** — Если выбрано, в пакет добавляется `attachments.csv`
4. **Data supplier name / location / comment** — Записывается в блок `DataSupplier` документа `INDEX.XML`; предзаполнено из раздела конфигурации `AuditExport` и редактируемо для каждого экспорта

### Жизненный цикл задачи {#job-lifecycle}

1. Нажатие **Start Export** проверяет период и почтовый ящик, создает задачу и возвращает на страницу
2. Задача выполняется в фоновом режиме (экспорты в очереди обрабатываются последовательно); таблица задач показывает текущий прогресс (обработано/всего писем с индикатором выполнения) через автоматический опрос (polling)
3. По завершении экспорта в строке задачи появляется кнопка **Download**
4. Выполняющиеся или стоящие в очереди задачи можно **отменить**

### История экспорта {#export-history}

Таблица истории под формой перечисляет последние экспорты с указанием времени, пользователя, периода, почтового ящика, количества писем, статуса и размера файла. История **сохраняется в базе данных** (таблица `AuditExportJobs`), поэтому она сохраняется после перезапуска приложения и является защищенной от изменений.

Файлы для скачивания хранятся в течение настраиваемого окна удержания (по умолчанию 30 дней, см. `AuditExport__RetentionDays`); по истечении этого времени ZIP-файлы удаляются ежедневной очисткой, в то время как строки в истории остаются.

> 📝 **Примечание**: Файлы экспорта хранятся внутри контейнера приложения. Если вам нужно хранить их длительное время, скачайте их и сохраните в своем репозитории доказательств аудита.

## 🔐 Аудит {#auditing}

Каждый экспорт создает две записи в логе доступа нового типа **Audit Data Export**:

1. **Start entry** — когда экспорт поставлен в очередь (с ID задачи, периодом, почтовым ящиком, опциями в формате JSON)
2. **Result entry** — когда экспорт завершен, не удался или был отменен (с ID задачи, периодом, почтовым ящиком, количеством писем, результатом и размером пакета в формате JSON)

Записи появляются на странице Logs, как и все остальные записи лога доступа, и могут быть отфильтрованы по новому типу. Выпадающий список фильтра типа подхватывает их автоматически.

## ⚙️ Конфигурация {#configuration}

Раздел `AuditExport` в `appsettings.json` (переменные окружения используют синтаксис с двойным подчеркиванием, например, `AuditExport__RetentionDays`):

| Настройка | Описание | По умолчанию |
|---|---|---|
| `DataSupplierName` | Значение по умолчанию для поля имени поставщика данных | empty |
| `DataSupplierLocation` | Значение по умолчанию для поля местоположения поставщика данных | empty |
| `Comment` | Значение по умолчанию для поля комментария | empty |
| `OutputDirectory` | Директория для генерируемых ZIP-файлов (относительные пути разрешаются относительно корня контента приложения) | `exports/audit` |
| `RetentionDays` | Дней до удаления завершенных файлов экспорта | `30` |
| `MaxRangeYears` | Максимально допустимый интервал между датой начала и конца периода | `10` |

## 🗄️ База данных {#database}

История экспорта хранится в таблице `mail_archiver."AuditExportJobs"` (создана миграцией `MigrateV2609_1`, применяется автоматически при запуске). Существующие таблицы этим функционалом не изменяются.

## 🔍 Устранение неполадок {#troubleshooting}

| Проблема | Причина / Решение |
|---|---|
| Кнопка скачивания отсутствует после перезапуска | Файлы экспорта находятся в контейнере; если контейнер был пересоздан или прошло окно удержания, ZIP-файл удален, а строка в истории осталась. Запустите экспорт заново. |
| "The period must not exceed X years" | Уменьшите период или увеличьте `AuditExport__MaxRangeYears`. |
| Задача долго находится в статусе *Running* | Большие архивы передаются потоком пачками по 1000 писем; прогресс обновляется непрерывно. Очень большие периоды могут занять некоторое время — проверьте счетчик обработано/всего. |
| Инструмент импорта сообщает о проблемах с кодировкой | Пакет имеет кодировку UTF-8 без BOM с объявленным флагом `UTF8` и явным разделителем записей; убедитесь, что инструмент читает `INDEX.XML` рядом с файлами данных (распакуйте весь ZIP, не открывайте файлы по отдельности изнутри ZIP). |

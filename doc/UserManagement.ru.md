# 👥 Управление пользователями и правами доступа к почтовым ящикам {#user-management-and-mailbox-permissions}

[← Назад к индексу документации](index.md)

## 📋 Обзор {#overview}

В данном руководстве приведены подробные инструкции по созданию новых учетных записей пользователей и назначению прав доступа к почтовым ящикам в приложении Mail Archiver. Также рассматриваются вопросы смены собственного пароля и принудительной смены пароля на только что установленном экземпляре.


## 🛠️ Предварительные условия {#prerequisites}

- Административный доступ к приложению Mail Archiver
- Существующие учетные записи электронной почты, настроенные в системе

## 🧑‍💻 Создание новой учетной записи пользователя {#creating-a-new-user-account}

1. Войдите в приложение Mail Archiver под учетной записью с административными привилегиями
2. Перейдите в раздел "Users" в главном меню
3. Нажмите кнопку "Create New User"
4. Заполните необходимую информацию о пользователе:
   - **Username**: Введите уникальное имя пользователя для нового пользователя
   - **Password**: Введите надежный пароль для пользователя
   - **Email**: Адрес электронной почты пользователя
   - **Admin**: Установите этот флаг, если пользователь должен иметь административные привилегии
   - **Self Manager**: Установите этот флаг, если пользователь должен иметь возможность управлять своими собственными почтовыми аккаунтами (редактировать существующие, добавлять новые, а также удалять аккаунты)
   - **active**: Должен быть отмечен, чтобы разрешить вход пользователю
5. Нажмите "Create User", чтобы сохранить новую учетную запись пользователя

## 🔐 Назначение прав доступа к почтовым ящикам пользователям {#assigning-mailbox-permissions-to-users}

1. После создания пользователя или при редактировании существующего перейдите в раздел "Users" в главном меню
2. Найдите в списке пользователя, которому вы хотите назначить почтовые аккаунты, и нажмите кнопку "Assign" рядом с этим пользователем
3. На странице "Assign Mail Accounts" вы увидите все доступные почтовые аккаунты и флажки, которые указывают, назначены ли они пользователю
5. Чтобы назначить новый почтовый аккаунт, отметьте соответствующий флажок для конкретного аккаунта
6. Чтобы удалить почтовый аккаунт у пользователя, снимите флажок
7. Нажмите "Save Assignments", чтобы применить изменения

## 👤 Права учетных записей пользователей {#user-account-permissions}

### Admin Users (Администраторы) {#admin-users}
Администраторы имеют полный доступ к приложению и могут:
- Управлять всеми учетными записями пользователей и их правами
- Иметь доступ ко всем почтовым аккаунтам в системе
- Просматривать все журналы доступа
- Выполнять любые административные задачи

### Self Manager Users (Самостоятельные менеджеры) {#self-manager-users}
Пользователи с правами Self Manager могут:
- Добавлять новые почтовые аккаунты в свою учетную запись
- Редактировать назначенные им существующие почтовые аккаунты
- Удалять назначенные им почтовые аккаунты
- Получать доступ к письмам из назначенных им аккаунтов и управлять ими (включая удаление)
- Просматривать свои собственные журналы доступа

### Standard Users (Стандартные пользователи) {#standard-users}
Стандартные пользователи имеют ограниченный доступ и могут:
- Просматривать архивированные письма из назначенных им почтовых аккаунтов
- Выполнять поиск в назначенных им почтовых аккаунтах
- Экспортировать письма из назначенных им аккаунтов
- Восстанавливать письма из назначенных им аккаунтов
- Получать доступ к вложениям в назначенных им аккаунтах

## 🔑 Смена собственного пароля {#changing-your-own-password}

Каждый пользователь с локальным паролем может изменить его без участия администратора:

1. Нажмите на ваше **имя пользователя** в правом верхнем углу, чтобы открыть меню пользователя.
2. Выберите **Change Password**.
3. Введите ваш **текущий пароль** и **новый пароль** дважды, затем подтвердите.

Новый пароль должен соответствовать требованиям ниже, и он должен **отличаться от текущего**.

> ℹ️ **Пользователи OIDC не могут изменить свой пароль здесь.** Страница ответит сообщением:
> *"OIDC users cannot change their password. Password management is handled by
> your OIDC provider."* Вместо этого измените пароль у вашего провайдера идентификации —
> см. [OIDC / SSO](OIDC_Implementation.md).

### Требования к паролю {#password-requirements}

- не менее **10 символов**
- как минимум одна **заглавная** буква
- как минимум одна **строчная** буква
- как минимум одна **цифра**
- как минимум один **специальный символ**

Форма отображает эти требования в виде живого чек-листа во время ввода. Те же правила применяются, когда администратор создает пользователя или сбрасывает пароль.

## ⚠️ Принудительная смена пароля (Первоначальная настройка) {#forced-password-change-initial-setup}

Свежеустановленный экземпляр запускается с учетными данными администратора из
конфигурации (`Authentication__Username` / `Authentication__Password`). Пока
этот пароль по умолчанию используется **и почтовый аккаунт еще не создан**, первый
вход заставляет сменить пароль:

- Предупреждающий баннер объясняет причину: *"For security reasons, you must change your
  password before continuing. This is required because you are using the default
  system credentials on a newly set up system."*
- Вы не можете уйти со страницы: *"You must change your password before
  you can continue using the system."*
- Новый пароль должен отличаться от текущего.
- После сохранения флаг сбрасывается, и вы перенаправляетесь на панель управления.

Как только вы измените пароль по умолчанию, принудительная смена больше не появится.

## 🕒 Сохранение сессии — флажок "Remember Me" {#staying-signed-in-the-remember-me-checkbox}

В форме входа есть флажок с надписью **Remember Me** (*angemeldet bleiben* в
немецком интерфейсе). Он делает ровно одну вещь: определяет, будет ли
токен аутентификации сессионным куки или постоянным.

| | Флажок не отмечен | Флажок отмечен |
|---|---|---|
| Срок действия куки | `Authentication__SessionTimeoutMinutes` (по умолчанию **60 минут**) | **7 дней** |
| Тип куки | Сессионный куки — удаляется при закрытии браузера | Постоянный куки — хранится на диске |
| Перезапуск браузера | Вам нужно войти снова | Вы остаетесь в системе |
| Тайм-аут бездействия | Продлевается при каждом запросе (`SlidingExpiration`) | Продлевается при каждом запросе, в пределах абсолютного лимита в 7 дней |
| Выход из системы | Немедленно завершает сессию | Немедленно завершает сессию |

Таким образом, флажок превращает режим "вход в рамках текущей сессии браузера, максимум 60 минут
бездействия" в режим "вход на срок до 7 дней, включая перезапуски браузера и
компьютера".

### Чего флажок НЕ делает {#things-the-checkbox-does-not-do}

- **Он не запоминает ваш пароль или имя пользователя.** Форма входа не
  заполняется автоматически при следующем визите; сохраняется только сессионный куки.
- **7 дней — это жесткий лимит, который нельзя настроить.** Значение фиксировано
  в коде (`Auth/Services/CookieAuthenticationService.cs`). Только
  время жизни не постоянного куки следует `Authentication__SessionTimeoutMinutes`.
- **Это не таймер бездействия.** 7 дней отсчитываются от момента входа; как только
  они истекают, требуется новый вход, даже если вы пользовались архивом минуту назад.
- **Он не работает после выхода из системы.** Нажатие *Logout* удаляет куки
  независимо от состояния флажка.

### Взаимодействие с 2FA {#interaction-with-2fa}

При включенной двухфакторной аутентификации состояние флажка запоминается во время
шага 2FA и применяется только после успешного прохождения второго фактора. Передача управления 2FA
происходит в сессии на стороне сервера, которая имеет собственный **60-минутный тайм-аут бездействия**: если код не введен в течение этого окна, вход прерывается, и
выбор флажка теряется вместе с ним.

### Взаимодействие с сессией приложения {#interaction-with-the-application-session}

Mail Archiver поддерживает вторую, отдельную серверную сессию для кратковременных
состояний — передача 2FA, выбор для пакетного восстановления и последнее состояние поиска.
У этой сессии фиксированный **60-минутный тайм-аут бездействия**, и она *не*
является постоянной. После перезапуска браузера с валидным куки "Remember Me" вы
авторизованы, но любая незавершенная операция, хранящаяся в той сессии, начнется заново.

### Взаимодействие с OIDC / SSO {#interaction-with-oidc-sso}

Пользователи, входящие через внешний провайдер идентификации, никогда не получают
постоянный куки: обратный вызов OIDC всегда начинает сессию с
`persistAuthentication: false`. Для таких аккаунтов флажок **не имеет эффекта** — то, как долго длится сессия,
решается настройками сессии провайдера идентификации.

> ⚠️ **Заметка по безопасности.** На общем или оставленном без присмотра компьютере не
> оставляйте флажок отмеченным — постоянный куки оставляет архив доступным на срок до 7 дней
> без пароля. В средах, где это неприемлемо, сократите
> `Authentication__SessionTimeoutMinutes` и требуйте от пользователей не использовать
> флажок, либо используйте OIDC, где провайдер применяет свою политику сессий.

## 🔒 Соображения безопасности {#security-considerations}

1. Используйте сложные пароли для всех учетных записей пользователей
2. Немедленно смените пароль администратора по умолчанию после установки
3. Назначайте права Admin только тем пользователям, которым они действительно необходимы
4. Назначайте права Self Manager только тем пользователям, которым нужно управлять своими аккаунтами
5. Регулярно проверяйте права пользователей, чтобы убедиться, что доступ соответствует их ролям
6. Удаляйте доступ пользователя, когда он больше не требуется
7. Используйте принцип наименьших привилегий — назначайте доступ только к тем почтовым аккаунтам, которые необходимы пользователям

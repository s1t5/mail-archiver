# 🔧 Руководство по обслуживанию базы данных {#database-maintenance-guide}

[← Назад к индексу документации](index.md)

## 📋 Обзор {#overview}

В данном руководстве объясняется, как настроить и использовать функцию автоматического обслуживания базы данных в Mail Archiver. Приложение включает встроенную фоновую службу, которая автоматически выполняет операции обслуживания базы данных PostgreSQL для поддержания оптимальной производительности и предотвращения разрастания базы данных.

## ⚠️ Важное примечание {#important-notice}

**Базы данных PostgreSQL не уменьшаются автоматически при удалении данных.** Когда вы удаляете электронные письма или почтовые ящики, база данных помечает это пространство как доступное для повторного использования, но фактический размер файла базы данных остается прежним. Это явление называется «разрастанием базы данных» (database bloat).

Mail Archiver включает службу автоматического обслуживания, которая ежедневно выполняет операции VACUUM ANALYZE, чтобы:
- Освободить место для повторного использования внутри базы данных
- Обновить статистику запросов для оптимальной производительности
- Предотвратить снижение производительности с течением времени
- Поддерживать работоспособность базы данных

## 🚀 Автоматическое обслуживание (Рекомендуется) {#automatic-maintenance-recommended}

### Конфигурация {#configuration}

Включите автоматическое обслуживание базы данных в вашем `appsettings.json` или через переменные окружения в `docker-compose.yml`:

#### Вариант 1: Через appsettings.json {#option-1-via-appsettingsjson}

```json
{
  "DatabaseMaintenance": {
    "Enabled": true,
    "DailyExecutionTime": "02:00",
    "TimeoutMinutes": 30
  }
}
```

#### Вариант 2: Через docker-compose.yml (Рекомендуется) {#option-2-via-docker-composeyml-recommended}

```yaml
services:
  mailarchive-app:
    image: s1t5/mailarchiver:latest
    environment:
      # Enable automatic database maintenance
      - DatabaseMaintenance__Enabled=true
      - DatabaseMaintenance__DailyExecutionTime=02:00
      - DatabaseMaintenance__TimeoutMinutes=30
```

### Параметры конфигурации {#configuration-options}

| Параметр | Тип | По умолчанию | Описание |
|-----------|------|---------|-------------|
| `Enabled` | boolean | `false` | Включить или выключить автоматическое обслуживание |
| `DailyExecutionTime` | string | `"02:00"` | Время суток для запуска обслуживания (формат HH:mm, 24-часовой) |
| `TimeoutMinutes` | integer | `30` | Максимальное время, разрешенное для операций обслуживания, в минутах |

### Как это работает {#how-it-works}

При включении служба обслуживания:

1. **Запускается автоматически** вместе с приложением
2. **Ожидает** наступления настроенного времени выполнения
3. **Выполняет VACUUM ANALYZE** для всей базы данных
4. **Регистрирует операцию** в журнале доступа (access log) приложения с указанием длительности
5. **Планирует следующий запуск** на следующий день

Операция обслуживания:
- ✅ Выполняется без простоя системы
- ✅ Не мешает нормальной работе приложения
- ✅ Обеспечивает полное логирование и мониторинг
- ✅ Освобождает место для повторного использования внутри базы данных
- ✅ Обновляет статистику запросов для повышения производительности

### Выбор времени выполнения {#choosing-the-execution-time}

Выберите время, когда активность вашей системы минимальна:
- **Рекомендуется**: Между 02:00 и 04:00 (ночные часы)
- **Учитывайте**: Настройки вашего часового пояса
- **Избегайте**: Часов пиковой нагрузки или окон резервного копирования

Примеры конфигураций:

```yaml
# Night maintenance (recommended)
- DatabaseMaintenance__DailyExecutionTime=02:00
```

### Мониторинг автоматического обслуживания {#monitoring-automatic-maintenance}

#### 1. Логи приложения {#1-application-logs}

Проверяйте логи приложения на предмет активности обслуживания:

```bash
# View recent logs
docker compose logs mailarchive-app | grep "Maintenance"

# View logs in real-time
docker compose logs -f mailarchive-app | grep "Maintenance"
```

#### 2. Журнал доступа (UI) {#2-access-log-ui}

Все операции обслуживания записываются в журнал доступа приложения:

1. Перейдите в **Logs** → **Access Log** в интерфейсе пользователя
2. Отфильтруйте по типу: **Database Maintenance**
3. Просматривайте время выполнения, длительность и любые ошибки

## 🔧 Ручное обслуживание (Для продвинутых пользователей) {#manual-maintenance-advanced}

### VACUUM FULL для восстановления дискового пространства {#vacuum-full-for-disk-space-recovery}

**⚠️ Требует остановки приложения**

VACUUM FULL сжимает базу данных и возвращает дисковое пространство операционной системе, но требует эксклюзивных блокировок.

```bash
# 1. Stop the application
docker compose stop mailarchive-app

# 2. Run VACUUM FULL
docker compose exec postgres psql -U mailuser -d MailArchiver -c \
  "VACUUM FULL VERBOSE ANALYZE;"

# 3. Start the application
docker compose start mailarchive-app
```

**Когда использовать:**
- После удаления больших почтовых ящиков
- Для освобождения значительного объема дискового пространства
- Во время запланированных окон технического обслуживания

**Важно:**
- Требуется свободное дисковое пространство, равное размеру таблицы
- На больших базах данных может занять несколько часов
- Блокирует все операции с базой данных
- Должно планироваться в часы минимальной нагрузки

Для получения подробной информации о ручных процедурах см. [Документацию PostgreSQL VACUUM](https://www.postgresql.org/docs/current/sql-vacuum.html).

## 📝 Резюме {#summary}

✅ **Включите автоматическое обслуживание** для оптимизации базы данных без участия пользователя
✅ **Мониторьте через журналы доступа**, чтобы подтвердить успешное выполнение операций
✅ **Используйте ручной VACUUM FULL** только тогда, когда необходимо восстановить дисковое пространство
✅ **Планируйте VACUUM FULL** во время окон технического обслуживания при массовых удалениях
✅ **Поддерживайте актуальность резервных копий** перед любыми операциями ручного обслуживания

Служба автоматического обслуживания берет на себя ежедневную оптимизацию базы данных, что в большинстве случаев избавляет от необходимости ручного вмешательства.

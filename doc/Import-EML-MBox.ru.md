# 📥 Импорт почты через Web UI (EML / MBox) {#importing-mail-in-the-web-ui-eml-mbox}

[← Назад к индексу документации](index.md)

## 📋 Обзор {#overview}

Помимо [интерфейса командной строки](CLI.md) и [импорта учетных записей через CSV](Account-Import.md), Mail Archiver может импортировать существующий почтовый архив **через веб-интерфейс**. Доступно две формы загрузки:

| Форма | Принимаемый файл | Результат |
|------|---------------|--------|
| **Import MBox** | `.mbox`, `.mbx` | Каждое сообщение из файла импортируется в **одну** выбранную вами папку |
| **Import EML** | `.zip`, содержащий `.eml` файлы | **Структура папок внутри ZIP** определяет, куда попадет каждое сообщение |

Обе формы архивируют сообщения в существующую учетную запись Mail Archiver, обе работают как **фоновые задачи** и обе **автоматически пропускают дубликаты** — повторный импорт того же файла не создает вторую копию.

> 💡 **Совет**: Если ваш архив уже находится на сервере в виде файла, лучше использовать
> [CLI](CLI.md). Это позволяет избежать загрузки через браузер и является
> лучшим выбором для многогигабайтных архивов.

## 🧭 Доступ {#access}

1. Откройте **Mail Accounts** в главном меню.
2. Используйте выпадающий список **Import** над списком учетных записей и выберите
   **Import MBox** или **Import EML**.

Формы доступны **администраторам** (для всех учетных записей) и **self managers**
(для назначенных им учетных записей); см.
[User Management](UserManagement.md#-user-account-permissions). В качестве целей импорта предлагаются только **включенные**
учетные записи — отключенную учетную запись выбрать нельзя.

## 📨 Import MBox {#import-mbox}

MBox — это формат, используемый большинством почтовых клиентов для экспортированных папок, а также для резервных копий типа `mbox`.

| Поле | Значение |
|-------|---------|
| **MBox File** | Файл `.mbox` / `.mbx` для загрузки |
| **Target Account** | Учетная запись Mail Archiver, которая принимает сообщения |
| **Target Folder** | Папка, в которую импортируются сообщения. Выберите одну из существующих папок учетной записи или введите новое имя — папка, которой еще не существует, будет **создана автоматически** во время импорта. По умолчанию — `INBOX`. |

Все сообщения из файла будут импортированы в эту единственную целевую папку. Сам файл MBox не содержит информации о папках, поэтому структура исходного почтового ящика не восстанавливается — если вам это необходимо, используйте способ EML/ZIP.

## 🗂️ Import EML {#import-eml}

Импорт EML ожидает **ZIP-архив**, элементами которого являются файлы `.eml`.

- Файлы `.eml` в **корне** ZIP-архива импортируются в `INBOX`.
- Файлы `.eml` в **подпапке** импортируются в папку с **тем же
  именем**, что и эта подпапка.

Таким образом, ZIP-архив со следующей структурой:

```
mailbox.zip
├── 2024-invoice.eml            → INBOX
├── Archive/
│   └── old-message.eml         → Archive
└── Projects/
    └── 2026/
        └── kickoff.eml         → Projects/2026
```

восстанавливает дерево папок вместе с сообщениями. Отдельные файлы `.eml` можно
загрузить, предварительно упаковав их в ZIP (`zip emails.zip *.eml`).

## ⚙️ Общее поведение {#shared-behaviour}

Обе формы ведут себя одинаково после нажатия **Start Import**:

- **Лимит размера файла** — настраивается с помощью `Upload__MaxFileSizeGB` (по умолчанию **10 GB**).
  В форме рядом с выбором файла отображается текущий лимит.
- **Фоновая обработка** — загрузка ставится в очередь как задача; вам не нужно
  держать браузер открытым.
- **Обработка дубликатов** — сообщения, которые уже есть в архиве, пропускаются
  и учитываются отдельно. Дубликаты сопоставляются по заголовку `Message-ID`.
- **Некорректные входные данные** — нечитаемые файлы пропускаются по отдельности,
  а информация о них выводится на странице статуса вместо прерывания всего импорта.
- **Прогресс** — вы сразу переходите на страницу статуса задачи, где отображаются
  ID задачи, имя файла, размер файла, статус, количество обработанных/всего сообщений
  и текущие счетчики. Та же задача отображается на странице [Jobs](BackgroundJobs.md).
- **Отмена** — выполняющийся импорт можно отменить на странице его статуса.
  Сообщения, импортированные до этого момента, остаются в архиве.
- **Журнал аудита** — импорт записывается в [access log](Logs.md), а значение
  хранилища для каждой учетной записи обновляется после завершения (см.
  [Per-Account Storage](AccountStorage.md)).

### Статусы задач {#job-statuses}

`Queued` → `Running` → `Completed` / `Failed` / `Cancelled`

Завершенная задача сообщает, сколько сообщений было импортировано, сколько не удалось
обработать и сколько было пропущено как дубликаты — например,
*"1420 imported, 3 failed, 87 duplicates"*. При успешном импорте загруженный
файл удаляется с сервера; записи об ошибках сохраняются на время жизни задачи,
чтобы вы могли увидеть, что было отклонено.

## ⚠️ На что стоит обратить внимание {#things-to-watch-out-for}

- **Неверный тип файла** — загрузка будет отклонена, если расширение не является одним из
  `.mbox`, `.eml` или `.zip`. Выбор в форме EML принимает только `.zip`, а в форме MBox — только `.mbox` и `.mbx`.
- **"0 imported, N duplicates"** — это не ошибка. Сообщения уже находятся
  в архиве, скорее всего, в результате предыдущего импорта или синхронизации того же источника.
- **Очень большие архивы** — файл MBox читается сообщение за сообщением, поэтому
  многогигабайтный файл требует времени даже при фоновой обработке. Следите за прогрессом
  на странице статуса, а не пытайтесь загрузить файл повторно.
- **Свободное место на диске** — загружаемый файл временно хранится на сервере,
  и для него требуется место рядом с базой данных вашего архива.
- **Имена папок со спецсимволами** — имена папок берутся из путей ZIP-архива
  или из вашего ввода; проверьте список папок учетной записи после импорта, если
  вы использовали необычные символы.

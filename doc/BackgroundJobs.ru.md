# ⚙️ Background Jobs {#background-jobs}

[← Back to Documentation Index](index.md)

## 📋 Overview {#overview}

Большая часть работы в Mail Archiver происходит без вашего непосредственного участия. Синхронизация почтового ящика, импорт файла MBOX, восстановление тысяч писем или экспорт архива могут занимать от нескольких минут до нескольких часов. Эти задачи выполняются как **background jobs** (фоновые задания) — вы запускаете их, и они продолжают работать, даже если вы закроете браузер.

Страница **Background Jobs** показывает, что выполняется в данный момент, что завершилось, а что пошло не так. Это место, куда стоит заглянуть, если что-то занимает больше времени, чем ожидалось, или если синхронизация завершилась с ошибками.

> **ℹ️ Страница администратора.** Для доступа к Background Jobs требуются права администратора; страница доступна из главного меню. Обычные пользователи её не видят — они по-прежнему могут запускать задания (например, пакетное восстановление), но мониторинг происходит здесь.

## 🗂️ Job Types {#job-types}

Страница группирует задания по типам. В каждом разделе отображается до **20 последних** заданий, при этом выполняющиеся и стоящие в очереди задания отсортированы сверху — чтобы старое задание не скрылось из виду из-за новых.

| Section | Что охватывает | Запуск из |
|---|---|---|
| **Synchronization Jobs** | Получение новой почты с почтового сервера | Автоматический график или *Sync now* в аккаунте |
| **MBox Import Jobs** | Импорт файлов `.mbox` | Mail Accounts → [Import MBOX](Import-EML-MBox.md#-import-mbox) |
| **EML Import Jobs** | Импорт файлов `.eml` / ZIP-архивов | Mail Accounts → [Import EML](Import-EML-MBox.md#-import-eml) |
| **Batch Restore Jobs** | Копирование выбранных писем обратно в почтовый ящик | Archive → select emails → Batch Restore |
| **Account Export Jobs** | Экспорт всего аккаунта (mbox / EML) | Mail Accounts → [Export](Export-Account.md) |
| **Selected Emails Export Jobs** | Экспорт выбранного набора писем | Archive → select emails → Export |
| **Email Deletion Jobs** | Удаление писем с сервера или из архива, включая массовое удаление на основе фильтров | Retention policy, ручное удаление или Archive → *Delete all matches* |
| **Account Deletion Jobs** | Удаление всего почтового аккаунта | Mail Accounts → Delete |
| **Offload** | Перенос почты за определенный период в другой аккаунт | Mail Accounts → Offload |

## 📊 Reading a Job Row {#reading-a-job-row}

Каждая строка содержит одинаковый набор столбцов:

| Column | Значение |
|---|---|
| **Job ID** | Короткий идентификатор — указывайте его при сообщении о проблеме |
| **Account** | Почтовый ящик, с которым работает задание |
| **Status** | Текущее состояние, см. таблицу ниже |
| **Progress** | Насколько продвинулось задание (обработано/всего, если известно) |
| **Created** | Когда задание было поставлено в очередь |
| **Started** | Когда оно фактически начало выполняться |
| **Completed** | Когда оно завершилось (пусто, пока задание выполняется) |
| **Duration** | Прошедшее время |

Некоторые типы заданий добавляют счетчики в столбец progress:

- **Success** / **Failed** — письма, обработанные успешно и с ошибкой
- **Skipped (duplicates)** — письма, которые уже есть в архиве (не импортируются повторно)
- **Recovered** — сообщения, повторно полученные после того, как сервер сообщил об их отсутствии
- **Malformed (skipped)** — сообщения, которые не удалось разобрать, и они были пропущены

### Status values {#status-values}

| Status | Значение |
|---|---|
| **Queued** | Ожидание запуска — выполняется другое задание или воркер занят |
| **Running** | В процессе выполнения |
| **Completed** | Успешно завершено |
| **CompletedWithErrors** | Завершено, но некоторые элементы не удалось обработать (MBox импорт) |
| **Failed** | Завершено с ошибкой |
| **Cancelled** | Остановил пользователь |
| **Rate Limited** | *Синхронизация приостановлена из-за ограничения пропускной способности. Будет возобновлена автоматически.* |
| **Timed Out** | Синхронизация превысила установленный лимит времени и была остановлена |

> **ℹ️ "Rate Limited" и "Timed Out" — это состояния, относящиеся только к синхронизации.** Они выглядят как ошибки, но это не так: синхронизация с ограничением скорости (rate-limited) возобновится сама, как только квота пропускной способности позволит, а синхронизация по таймауту (timed-out) продолжится с контрольной точки при следующем запуске. См. [Rate Limit Handling](RateLimitHandling.md) и [Mail Synchronization](Synchronization.md).

### Почему прогресс может замереть на 0% {#why-progress-can-sit-at-0}

Прогресс измеряется **завершенными папками**, а не отдельными письмами:

> *Прогресс измеряется завершенными папками. Большая папка (например, INBOX) удерживает полосу на 0%, пока она не будет полностью обработана.*

В почтовом ящике, где в INBOX находится большая часть почты, полоса может долго оставаться на 0%, а затем резко прыгнуть вперед. Это ожидаемое поведение — задание работает, оно просто еще не закончило обработку своей первой большой папки.

## 🔄 The Page Refreshes Itself {#the-page-refreshes-itself}

Пока страница открыта, она перезагружается каждые **30 секунд**, поэтому вы можете оставить её во вкладке и наблюдать за прогрессом, ничего не нажимая. Метка показывает, когда данные обновлялись в последний раз.

Перезагрузка отменяется в тот момент, когда вы нажимаете на ссылку или кнопку — иначе ваш клик попадет на страницу, которая заменяется прямо под курсором.

**Настраиваемо:** `Jobs:RefreshSeconds` в `appsettings.json` (по умолчанию `30`).
Установите `0`, чтобы отключить автоматическую перезагрузку. Каждая перезагрузка перестраивает страницу из всех источников заданий, поэтому слишком короткий интервал на установке с большим количеством аккаунтов создает реальную нагрузку — и эта нагрузка умножается на каждую открытую вкладку.

```json
"Jobs": {
  "RefreshSeconds": 30
}
```

## 🛑 Cancelling a Job {#cancelling-a-job}

Задания, поддерживающие отмену, отображают кнопку **Cancel Job**, которая спрашивает:

> *Are you sure you want to cancel this job?*

Задания импорта используют формулировку **Cancel Import** / *Are you sure you want to cancel this import job?*

Отмена доступна для заданий **synchronization, batch restore, selected-emails export и email deletion**. Задание останавливается сразу после завершения текущего элемента; статус меняется на **Cancelled**.

> **⚠️ Отмена — это не откат (rollback).** Письма, которые уже были импортированы, восстановлены, экспортированы или удалены, остаются в этом состоянии. Отмена лишь мешает заданию делать *дальнейшие* действия — она не отменяет то, что уже было сделано. Для задания на удаление это означает, что уже удаленные письма пропали безвозвратно.

Задания по импорту аккаунтов и MBox нельзя отменить с этой страницы; вместо этого остановите их на странице импорта самого аккаунта.

## ⚠️ Sync Failures and "Acknowledge Failures" {#sync-failures-and-acknowledge-failures}

Когда синхронизация завершается со статусом **Failed**, в строке задания появляется опция **Acknowledge Failures**. Это единственное действие на странице, которое меняет поведение системы в будущем, поэтому его важно понимать.

Каждый запуск синхронизации начинается с того места, где остановился предыдущий, используя **checkpoint** (контрольную точку). Если синхронизация дает сбой на каких-то письмах, контрольная точка остается *перед* этими письмами, чтобы следующий запуск попробовал их снова. Это безопасное поведение по умолчанию — ничего не пропускается незаметно.

Но если ошибки являются постоянными (поврежденное сообщение, папка, которую сервер отказывается отдавать), каждая последующая синхронизация будет пытаться обработать их снова, и синхронизация будет постоянно спотыкаться в одном и том же месте.

**Acknowledge Failures** разрешает этот тупик, сдвигая контрольную точку за проблемные письма. Подтверждение явно указывает на последствия:

> *This will advance the sync timestamp to the completion time of this job, so the next sync will be a normal incremental sync. The failed emails will not be retried. Continue?*

В случае успеха вы увидите: *"Sync timestamp has been advanced. The next sync will be incremental."*

> **⚠️ Подтверждайте только после того, как изучите ошибки.** После подтверждения эти письма **не** будут обработаны повторно — они будут отсутствовать в архиве, если вы не получите их другим способом. Сначала проверьте детали ошибки, и если причина в неправильной конфигурации, исправьте её перед подтверждением. Подробности о поведении контрольных точек см. в [Mail Synchronization](Synchronization.md).

Действие "Acknowledge" записывается в лог доступа как *SyncAcknowledgeFailures* с указанием количества неудачных писем и аккаунта, так что это можно отследить позже.

## 👁️ What You Cannot Do Here {#what-you-cannot-do-here}

- **Нет кнопки повтора (retry).** Неудачное задание нельзя перезапустить с этой страницы — запустите операцию заново оттуда, где вы её начали (sync, import, export).
- **Нет редактирования.** Параметры задания фиксируются в момент создания.
- **Только последние 20 для каждого типа.** Более старые задания не отображаются. Для долгосрочного хранения записей используйте лог доступа и лог приложения — см. [Access Logging](Logs.md) и [Docker Compose Logs](DockerComposeLogs.md).

## ❓ Troubleshooting {#troubleshooting}

| Symptom | Likely cause | What to do |
|---|---|---|
| Job stays **Queued** | Другое задание того же воркера выполняется | Подождите; проверьте другие разделы на наличие долго выполняющегося задания |
| Progress stuck at 0% | Одна большая папка всё еще обрабатывается | Это нормально — см. "Why progress can sit at 0%" |
| Sync repeatedly **Failed** on the same account | Постоянные ошибки в отдельных письмах | Изучите ошибки, устраните причину, затем подтвердите (acknowledge) |
| Sync shows **Rate Limited** | Достигнута квота пропускной способности | Ничего — она возобновится автоматически |
| Sync shows **Timed Out** | Почтовый ящик больше лимита времени | Синхронизация продолжится с контрольной точки при следующем запуске; см. [Synchronization](Synchronization.md) |
| **CompletedWithErrors** on an MBox import | Некоторые сообщения повреждены | Счетчики покажут, сколько именно; остальные были импортированы |
| Job disappears after reload | Задание вышло за пределы окна "последних 20" | Проверьте лог приложения для получения его финального статуса |
| Page reloads while you work | Автоматическое обновление каждые 30 с | Установите `Jobs:RefreshSeconds` в `0` |

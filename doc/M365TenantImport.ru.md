# Microsoft 365 Tenant Mailbox Import {#microsoft-365-tenant-mailbox-import}

[← Back to Documentation Index](index.md)

## Overview {#overview}

Mail Archiver позволяет создавать почтовые аккаунты Microsoft 365 для более чем одного почтового ящика в одном и том же тенанте с помощью одной формы создания. Это полезно при подключении клиента или организации, где необходимо архивировать все или выбранные подмножества почтовых ящиков Microsoft 365.

Импорт тенанта использует учетные данные приложения Microsoft Graph, настроенные в форме, и создает один почтовый аккаунт Mail Archiver для каждого импортируемого почтового ящика.

## Prerequisites {#prerequisites}

Перед использованием импорта тенанта завершите настройку регистрации приложения Microsoft 365, описанную в [Azure App Registration and Retention Policy Guide](AZURE_APP_REGISTRATION_M365.md).

Вам понадобятся следующие значения из Microsoft Entra ID:

- **Client ID** / Application ID
- **Client Secret**
- **Tenant ID** / Directory ID

Регистрация приложения должна иметь **разрешения приложения** (application permissions) Microsoft Graph, которые позволяют Mail Archiver считывать почтовые ящики тенанта. В дополнение к разрешениям, необходимым для обычного архивирования аккаунтов M365, для импорта тенанта требуется следующее разрешение:

- **User.Read.All** – требуется для получения списка пользователей тенанта и адресов их почтовых ящиков.

При импорте тенанта в форме создания в качестве провайдера выбирается **Microsoft 365 (tenant)**.

### Filtering {#filtering}

Импорт тенанта и управление тенантом (Tenant Management) автоматически исключают:
- **Гостевые учетные записи** (`userType == "Guest"`) — приглашенные внешние пользователи, не имеющие собственных почтовых ящиков в тенанте.
- **Пользователей без лицензии Exchange Online** — в списке отображаются только пользователи с активным планом обслуживания Exchange в их `assignedPlans`. Это позволяет избежать импорта аккаунтов, которые невозможно архивировать.

## Import Modes {#import-modes}

Импорт тенанта поддерживает два режима:

### Import all listed mailboxes {#import-all-listed-mailboxes}

Используйте этот режим, когда каждый почтовый ящик, возвращаемый Microsoft Graph, должен быть создан как аккаунт Mail Archiver.

- Mail Archiver загружает список почтовых ящиков тенанта из Microsoft Graph.
- Уже существующие почтовые аккаунты M365 пропускаются.
- Если включена опция **Skip disabled mailboxes**, отключенные пользователи не включаются в список почтовых ящиков.

### Import selected mailboxes only {#import-selected-mailboxes-only}

Используйте этот режим, когда необходимо архивировать только определенные почтовые ящики в тенанте.

- Сначала загрузите список почтовых ящиков тенанта.
- Отключите **Import all listed mailboxes**.
- Выберите почтовые ящики, которые должны быть импортированы.
- Отправьте форму, чтобы создать аккаунты только для выбранных почтовых ящиков.

## Step-by-Step Usage {#step-by-step-usage}

1. Войдите в Mail Archiver как пользователь, имеющий право создавать почтовые аккаунты.
2. Откройте **Mail Accounts** > **Create**.
3. Выберите **Microsoft 365 (tenant)** в качестве провайдера.
4. Введите учетные данные Microsoft 365:
   - **Client ID**
   - **Client Secret**
   - **Tenant ID**
5. Введите префикс **Account name**, который будет использоваться для создаваемых аккаунтов.
6. Выберите, следует ли пропускать отключенные почтовые ящики.
7. Нажмите **Load mailboxes**, чтобы вывести список почтовых ящиков тенанта.
8. Выберите желаемое поведение импорта:
   - Оставьте **Import all listed mailboxes** включенным, чтобы импортировать все найденные ящики.
   - Отключите его и выберите отдельные ящики, чтобы импортировать только конкретные адреса.
9. Нажмите **Save**.

После создания Mail Archiver перенаправит вас обратно к списку почтовых аккаунтов и покажет, сколько аккаунтов тенанта было импортировано и сколько существующих аккаунтов было пропущено.

## Account Naming {#account-naming}

При импорте тенанта Mail Archiver использует значение, введенное в поле **Account name**, в качестве префикса для каждого создаваемого аккаунта почтового ящика.

Пример:

- Введенное имя аккаунта: `Test GmbH`
- Почтовый ящик тенанта: `mailbox@example.com`
- Созданное имя аккаунта: `Test GmbH - <mailbox@example.com>`

Это упрощает идентификацию импортированных аккаунтов, принадлежащих одному и тому же тенанту или клиенту.

## Existing Accounts {#existing-accounts}

Если почтовый ящик уже существует в Mail Archiver как аккаунт Microsoft 365, импорт тенанта пропускает его вместо создания дубликата. Обнаружение существующих аккаунтов основано на адресе электронной почты ящика и провайдере M365.

Список почтовых ящиков также может показывать, существует ли ящик, еще до отправки импорта.

## Disabled Mailboxes {#disabled-mailboxes}

Флажок **Skip disabled mailboxes** управляет тем, должны ли отключенные пользователи тенанта быть исключены из списка почтовых ящиков.

- Включено: отображаются и импортируются только активные пользователи тенанта.
- Выключено: отключенные пользователи тенанта могут появиться в списке и могут быть импортированы, если они выбраны или если выбран режим импорта всех ящиков.

## Tenant Management {#tenant-management}

В дополнение к импорту через форму создания, Mail Archiver предоставляет специальную страницу **Tenant Management** для администраторов. Она доступна из индекса Mail Accounts через кнопку **Tenant Management** (иконка здания) рядом с любым аккаунтом Microsoft 365.

Tenant Management полезен для добавления почтовых ящиков, которые не были импортированы изначально — например, когда в тенанте создаются новые ящики после первоначального подключения или когда аккаунты были пропущены ранее.

### How it differs from the create-form tenant import {#how-it-differs-from-the-create-form-tenant-import}

- Учетные данные Microsoft 365 (Client ID, Client Secret, Tenant ID) **не вводятся заново**. Они берутся из исходного аккаунта, на кнопке которого была нажата кнопка управления.
- Список почтовых ящиков тенанта загружается автоматически при открытии страницы (кнопка "Load mailboxes" не требуется).
- Уже импортированные ящики помечаются значком "already exists" и не могут быть выбраны повторно.
- Доступ к Tenant Management имеют только администраторы.

### Step-by-Step Usage {#step-by-step-usage}

1. Войдите в Mail Archiver как администратор.
2. Откройте **Mail Accounts**.
3. Найдите аккаунт Microsoft 365, тенант которого вы хотите настроить, и нажмите кнопку **Tenant Management** рядом с ним.
4. Страница загрузится и выведет список всех почтовых ящиков, возвращаемых Microsoft Graph для тенанта исходного аккаунта.
   - Почтовые ящики, которые уже существуют в Mail Archiver как аккаунты M365, помечены значком "already exists" и не могут быть выбраны.
   - Отключенные пользователи тенанта не отображаются; Tenant Management всегда пропускает отключенные ящики.
5. Выберите почтовые ящики, которые вы хотите добавить.
6. Введите префикс **Account name**, который будет использоваться для новых аккаунтов (схема именования `{prefix} - <{email}>` идентична импорту через форму создания).
7. При необходимости настройте **Delete After Days** и **Local Retention Days** для новых аккаунтов.
8. Нажмите **Add selected mailboxes**.

После создания Mail Archiver перенаправит вас к списку почтовых аккаунтов и покажет, сколько ящиков было добавлено.

### Searching mailboxes {#searching-mailboxes}

Для крупных тенантов с несколькими тысячами ящиков поле поиска над списком позволяет фильтровать ящики по отображаемому имени или адресу электронной почты. Фильтр нечувствителен к регистру и применяется мгновенно при вводе. Функции **Select all** и **Clear selection** работают только с текущими видимыми (отфильтрованными) ящиками, поэтому фильтрация — это безопасный способ выбрать определенное подмножество, не затрагивая скрытые записи.

### Renaming existing accounts {#renaming-existing-accounts}

Флажок **Rename existing accounts** применяет схему именования `{prefix} - <{email}>` ко всем аккаунтам M365, которые используют ту же регистрацию приложения (Client ID и Tenant ID), что и исходный аккаунт. Это полезно для нормализации имен аккаунтов после первоначального импорта, если имена были непоследовательными.

При установке этого флажка сохранение формы переименует каждый соответствующий аккаунт — включая исходный аккаунт — независимо от того, выбраны ли новые почтовые ящики для импорта. Вы можете использовать эту опцию отдельно (не выбирая новых ящиков), чтобы нормализовать имена без добавления новых аккаунтов.

### Mailbox limit {#mailbox-limit}

Одна операция Tenant Management может добавить не более `TenantManagement__MaxSelectedMailboxes` почтовых ящиков за раз (по умолчанию `1000`). Это защищает от случайного массового импорта и чрезмерной нагрузки на Microsoft Graph / базу данных. Если вам нужно импортировать больше ящиков, запустите операцию несколько раз. Инструкции по изменению этого лимита см. в [Setup Guide](Setup.md#-tenant-management-settings).

### Permissions required {#permissions-required}

Tenant Management использует те же разрешения приложения Microsoft Graph, что и импорт через форму создания. Регистрация приложения исходного аккаунта должна иметь:

- Разрешения, необходимые для обычного архивирования аккаунтов M365, **и**
- **User.Read.All** — требуется для получения списка пользователей тенанта и адресов их почтовых ящиков.

Для первоначальной настройки см. [Azure App Registration and Retention Policy Guide](AZURE_APP_REGISTRATION_M365.md).

### Audit logging {#audit-logging}

Каждый просмотр страницы Tenant Management и каждая операция добавления записываются в лог доступа, включая количество перечисленных или добавленных ящиков и использованный исходный аккаунт.

# 💾 Отображение хранилища для каждого аккаунта {#per-account-storage-display}

[← Назад к индексу документации](index.md)

## 📋 Обзор {#overview}

Таблица «Account Overview» в Dashboard и таблица «Show All» в MailAccounts содержат столбец **Storage**. Этот столбец показывает, сколько места в базе данных занимает каждый аккаунт, включая **все поля каждого архивного письма** плюс **все вложения**.

## ⚙️ Как это работает {#how-it-works}

Значения хранилища **кешируются** в таблице базы данных `AccountStorageCache`. Это означает, что веб-страницы считывают предварительно вычисленные значения вместо выполнения ресурсоемкого запроса каждый раз, когда вы открываете Dashboard или список аккаунтов. Кеш поддерживается в актуальном состоянии независимой фоновой службой (`AccountStorageRefreshService`).

Для каждого аккаунта служба запрашивает у PostgreSQL сумму `pg_column_size` для каждой колонки строк аккаунта в таблице `ArchivedEmails`. Это охватывает **все поля письма** (Subject, From, To, Cc, Bcc, Body, HtmlBody, RawHeaders, ContentHash и т. д.), включая сжатие PostgreSQL и внестрочное хранение (TOAST). Размер внестрочного значения считывается из его указателя TOAST, поэтому расчет сканирует только саму таблицу и никогда не загружает тела писем. Часть вложений добавляется отдельно как логическая сумма `EmailAttachment.Size`.

Служба обновления обновляет кеш в трех ситуациях:

1. **Заполнение при запуске (Startup backfill)** — После новой установки или после обновления до версии, в которой появилась эта функция, каждый аккаунт изначально не имеет кешированного значения. Служба проходит по всем аккаунтам один за другим и вычисляет первое значение.
2. **Ежедневное обновление** — Один раз в день в настроенное время (по умолчанию `02:30`) служба пересчитывает все аккаунты в качестве меры предосторожности.
3. **Немедленное обновление** — После синхронизации почты, импорта EML, импорта MBOX или удаления по правилам хранения (retention deletion), соответствующий аккаунт пересчитывается немедленно, чтобы отображаемое значение оставалось актуальным.

## 🤔 Почему сначала отображается "0 B" {#why-0-b-is-shown-at-first}

Когда функция только включена или когда создается новый аккаунт, строка кеша для этого аккаунта еще не существует. Служба обновления работает в фоновом режиме и вычисляет аккаунты **по одному**, с небольшой задержкой между каждым аккаунтом, чтобы очень большие архивы не перегружали базу данных.
Пока служба не обработает аккаунт, интерфейс отображает **"0 B"** в качестве заглушки. Это совершенно нормально. Как только фоновая служба закончит обработку этого аккаунта, реальное значение появится при следующей загрузке или обновлении страницы.
Для больших существующих архивов заполнение при запуске может занять несколько минут или дольше. Служба отслеживает свой прогресс в специальной таблице (`AccountStorageBackfillState`), поэтому, если приложение будет перезапущено в середине процесса, оно просто продолжит с того места, где остановилось — ни один аккаунт не будет вычислен дважды.

## 🔧 Конфигурация {#configuration}

Функцию можно настроить в `appsettings.json` или через переменные окружения. См. раздел **Account Storage Settings** в [Setup.md](Setup.md) для получения информации обо всех доступных опциях, включая:

- `AccountStorage__Enabled`: Включить или выключить службу обновления (по умолчанию `true`).
- `AccountStorage__DailyExecutionTime`: Время для ежедневного полного обновления (по умолчанию `02:30`).
- `AccountStorage__BackfillDelayMs`: Пауза между аккаунтами во время заполнения при запуске (по умолчанию `5000` мс).
- `AccountStorage__RefreshBatchDelayMs`: Пауза между аккаунтами во время ежедневного обновления (по умолчанию `1000` мс).
- `AccountStorage__CommandTimeoutSeconds`: Таймаут команды базы данных для расчета хранилища по каждому аккаунту (по умолчанию `300` секунд). Увеличьте это значение для очень больших архивов, где сканирование `pg_column_size` занимает больше времени.

> 💡 **Совет**: Вам **не нужно** включать `DatabaseMaintenance__Enabled` для работы этой функции. Служба обновления хранилища работает независимо.

# 📤 Date-Windowed Offload {#date-windowed-offload}

[← Back to Documentation Index](index.md)

## 📋 Overview {#overview}

Offload (выгрузка) добавляет архивированную почту новее определенной даты в другой почтовый ящик и оставляет все, что старше, в архиве. Это решение предназначено для миграций, когда в новом почтовом ящике должна храниться только недавняя почта, в то время как полная история остается доступной через Mail Archiver.

Оно отличается от [Copy All Emails to Another Mailbox](MailboxMigration.md) пятью спосомами:

| | Copy All Emails | Offload |
|---|---|---|
| Фильтр даты | нет, все или ничего | cutoff (отсечка), с необязательной верхней границей |
| Повторяемость | нет, добавляет все заново | да, пропускает то, что уже есть в целевом ящике |
| Исключение папок | нет | да, настраивается |
| Переименование папок | нет | да, настраивается |
| Предварительный просмотр | нет | dry run (холостой запуск) сообщает отчет по папкам без записи |

Offload всегда только добавляет данные в целевой ящик. Он никогда не удаляет ничего из архива и никогда не затрагивает исходный почтовый ящик.

## 🔁 Повторный запуск безопасен {#repeating-a-run-is-safe}

Перед первым добавлением весь целевой почтовый ящик индексируется, и каждое сообщение проверяется на его наличие. Таким образом, повторный запуск ничего не добавляет из того, что уже прибыло, а вместо этого сообщает, что сообщения уже присутствуют. Это имеет три практических последствия:

- Прерванный запуск можно восстановить, просто запустив его снова.
- Завершенный запуск можно повторить в качестве проверочного прохода. Правильный результат — ничего не добавлено и все уже присутствует.
- Сообщения, удаленные в целевом ящике, появятся при следующем запуске, так как их больше нет в индексе.

Два критерия определяют, присутствует ли сообщение, в следующем порядке:

1. **Message-ID**, нормализованный. Это выполняет почти всю работу.
2. **Отпечаток (fingerprint)** по отправителю, получателям, теме и времени отправки с точностью до двух секунд. Это охватывает сообщения, чей сохраненный Message-ID отсутствует или поврежден. Такие сообщения невозможно восстановить с их оригинальным Message-ID, поэтому без этого второго критерия они бы дублировались при каждом запуске.

Задача сообщает, сколько совпадений было найдено по отпечатку отдельно, так как это критерий, который может незаметно дать сбой.

## ⚙️ Configuration {#configuration}

Новый раздел `Offload` со значениями по умолчанию, воспроизводящими предыдущее поведение:

```json
"Offload": {
  "MaxConcurrentJobs": 1,
  "PrefetchMaxMessages": 500000,
  "ExcludedSourceFolders": [],
  "FolderRenameMap": {},
  "MarkAsSeen": true
}
```

| Key | Default | Purpose |
|---|---|---|
| `MaxConcurrentJobs` | `1` | Сколько задач восстановления или offload могут выполняться одновременно. Значение 1 сохраняет строго последовательное поведение, которое всегда было у очереди задач. Максимум одна задача на целевой почтовый ящик выполняется независимо от этого значения. |
| `PrefetchMaxMessages` | `500000` | Верхняя граница количества сообщений, индексируемых из целевого почтового ящика. Выше этого значения проверка дубликатов сужается до одной папки и записывает это в лог. |
| `ExcludedSourceFolders` | empty | Исходные папки, которые никогда не выгружаются. Проверяется перед переименованием и охватывает подпапки. |
| `FolderRenameMap` | empty | Перезаписывает начальные сегменты пути исходной папки. |
| `MarkAsSeen` | `true` | Помечать ли добавленную почту как прочитанную. |

Обе настройки папок намеренно поставляются пустыми. Перезапись или удаление папок без запроса пользователя удивило бы тех, кто уже использует путь восстановления, поэтому запуск без конфигурации мигрирует все, включая папки со спамом, и создает второй набор специальных папок рядом с собственными папками целевого ящика.

### Folder exclusions and renaming {#folder-exclusions-and-renaming}

Для миграции из Exchange в Dovecot эти две настройки обычно выглядят так:

```json
"ExcludedSourceFolders": ["Junk E-Mail", "Deleted Items"],
"FolderRenameMap": {
  "Sent Items": "Sent",
  "Deleted Items": "Trash",
  "Junk E-Mail": "Junk"
}
```

Без карты переименования каждый мигрированный почтовый ящик в итоге будет иметь и `Sent`, и `Sent Items`, так как Dovecot предварительно создает свои собственные папки special-use.

Стоит знать четыре вещи о том, как они применяются, так как каждая из них может стать сюрпризом:

1. **Исключения проверяются в первую очередь** по исходному имени. Если переименование произойдет первым, исключение для `Deleted Items` никогда не сработает, как только оно станет `Trash`.
2. **Переименование перезаписывает самый длинный совпадающий префикс пути** на границах сегментов. `Sent Items`, становясь `Sent`, также превращает `Sent Items/2019` в `Sent/2019` и оставляет `Sent Items Archive` без изменений.
3. **Сопоставление нечувствительно к регистру**, и `/`, и `\` считаются разделителями.
4. **Две исходные папки могут объединиться в одну целевую.** То, что `Sent Items` и `Sent` оба становятся `Sent`, — это нормально и не приводит к открытию целевой папки дважды.

Изменение карты переименования между двумя запусками не приводит к дублированию, так как проверка дубликатов охватывает весь целевой почтовый ящик, а не одну разрешенную папку.

## 🖥️ Running it from the interface {#running-it-from-the-interface}

На странице с деталями аккаунта **Offload to Another Mailbox** открывает форму с целевым почтовым ящиком, корневой папкой цели, опцией сохранения структуры папок, временным окном, переключателем dry run и опцией пометки добавленной почты как прочитанной. Настроенные исключения и карта переименования отображаются только для чтения, поэтому запуск никогда не будет сюрпризом.

Задача ставится в очередь, а ее прогресс и отчет по папкам появляются на странице статуса задач и в разделе **Jobs**. Отчет по папкам содержит имена исходных папок, поэтому он показывается только пользователю, запустившему задачу, и администраторам.

Целевым почтовым ящиком может быть отключенный IMAP-аккаунт, например, для подготовки цели миграции перед ее запуском; запуск завершится с ошибкой при подключении, если цель недоступна. Аккаунты Microsoft 365 не могут быть целями для offload; путь восстановления через Graph остается без изменений.

### Who may run it {#who-may-run-it}

Администраторы могут выполнять offload между любыми двумя аккаунтами. Self-manager может выполнять offload **только между аккаунтами, назначенными ему**, с обеих сторон: в качестве источника, так как страница аккаунта уже ограничена этим контекстом, и в качестве цели, так как список целей сужен до того же набора, и запрос проверяется по нему снова при запуске задачи. Таким образом, self-manager с одним назначенным аккаунтом не имеет подходящей цели, и ему сообщается об этом.

Ограничение области действия (scoping) исходит из `IAccountAccessResolver`, того же резолвера, который используют REST API и MCP-сервер, поэтому существует единое определение того, кто может использовать тот или иной почтовый ящик. Само решение находится в `OffloadTargetEligibility`, которую вызывают и список целей, и проверка запроса, поэтому то, что предлагает форма, и то, что принимает сервер, не могут разойтись.

## ⌨️ Running it from the command line {#running-it-from-the-command-line}

```bash
docker compose exec mailarchive-app dotnet MailArchiver.dll \
  --offload --source-account-id 3 --target-account-id 7 \
  --since 2025-08-01 \
  [--until 2026-08-01] [--target-folder INBOX] \
  [--preserve-folders] [--dry-run] [--no-mark-seen]
```

| Argument | Meaning |
|---|---|
| `--source-account-id` | Аккаунт, из которого нужно читать архивированную почту. Обязательно. |
| `--target-account-id` | IMAP-аккаунт, в который нужно добавлять почту. Обязательно, и он должен отличаться от источника. |
| `--since` | Включительная нижняя граница даты отправки, `YYYY-MM-DD`. Обязательно. |
| `--until` | Необязательная включительная верхняя граница. |
| `--target-folder` | Корневая папка в целевом почтовом ящике. По умолчанию `INBOX`. |
| `--preserve-folders` | Восстановить структуру исходных папок под корнем. |
| `--dry-run` | Сообщить о том, что произойдет, ничего не добавляя. |
| `--no-mark-seen` | Добавлять без флага Seen. |

Коды выхода:

| Code | Meaning |
|---|---|
| `0` | Все было добавлено или уже присутствует. |
| `1` | Как минимум одно сообщение не удалось обработать, или сам запуск завершился ошибкой. |
| `2` | Вызов был неверным: неверные или отсутствующие аргументы, неизвестный аккаунт, цель не является IMAP, источник равен цели. |

Один вызов обрабатывает один почтовый ящик, что позволяет автоматизировать работу с целым парком ящиков с помощью CSV-файла с источником, целью и cutoff.

> **Запуск нескольких задач одновременно.** Правило «одна задача на одну цель» действует только внутри одного процесса, поэтому два одновременных вызова командной строки к *одному и тому же* целевому ящику могут каждый получить свой индекс дубликатов до того, как другой начнет запись, и в итоге оба могут добавить одну и ту же почту. Разделяйте работу так, чтобы каждый одновременный вызов имел другую цель, что является обычным случаем, когда каждая строка в CSV — это отдельный почтовый ящик.

## 🗓️ How the cutoff is interpreted {#how-the-cutoff-is-interpreted}

- Фильтр применяется к **дате отправки**, а не к моменту, когда сообщение было архивировано. Метка времени архивации — это время запуска процесса архивации, и она не имеет значения для cutoff.
- Относительное окно, такое как «последние двенадцать месяцев», **преобразуется в фиксированную дату в момент создания задачи**. Задача может выполняться долго и повторяться впоследствии, и она должна выбирать одну и ту же почту каждый раз; сохраненное относительное окно со временем бы смещалось.
- Cutoff интерпретируется в **настроенной часовой зоне отображения**, той же самой, которую показывает экран поиска, и нижняя граница является включительной с 00:00 этого дня. Верхняя граница включает в себя весь этот день. Относительные окна («последние N месяцев») также преобразуются в этой часовой зоне отображения, так же, как хранится `SentDate`.

### Known limitation {#known-limitation}

- Когда индекс дубликатов достигает `Offload:PrefetchMaxMessages`, область действия сужается и фиксируется в логах, вместо того чтобы пытаться повторить проверку для одной папки. Резервный механизм `restrictToFolder`, предлагаемый построителем индекса, в настоящее время не используется путем offload; увеличением лимита является поддерживаемым решением.

## 📋 A migration, end to end {#a-migration-end-to-end}

1. Создайте целевые почтовые ящики. Для массового создания см. CSV bulk import в [Account Import](Account-Import.md).
2. Настройте `Offload:ExcludedSourceFolders` и `Offload:FolderRenameMap`. Оба по умолчанию пусты, поэтому пропуск этого шага приведет к миграции папок со спамом и созданию дублирующихся специальных папок.
3. Подтвердите, что каждый исходный почтовый ящик полностью архивирован, прежде чем выполнять offload.
4. **Проведите dry run для всего.** Проверьте количество сообщений и разрешенные имена целевых папок перед тем, как что-либо будет записано.
5. Реальный запуск. Начните с `MaxConcurrentJobs` равного 2 и увеличивайте его только после наблюдения за тем, как справляется целевой сервер; Dovecot ограничивает количество одновременных соединений на пользователя и на IP.
6. Повторите запуск для проверки. Ожидайте, что ничего не будет добавлено и все уже будет присутствовать.
7. Отключите исходные аккаунты.

Пропускная способность ограничена `BatchOperation:PauseBetweenEmailsMs`, которая по умолчанию составляет 50 мс, что позволяет выполнять не более двадцати операций добавления в секунду, прежде чем начнет учитываться задержка сервера.

## 🔍 What the counters mean {#what-the-counters-mean}

| Counter | Meaning |
|---|---|
| Appended | Записано в целевой ящик. При dry run — то, что было бы записано. |
| Already present | Уже находилось в целевом ящике по любому из критериев. |
| of those by fingerprint | Сколько было распознано по второму критерию, а не по Message-ID. |
| Excluded folder | Пропущено, так как исходная папка исключена. |
| Failed | Не удалось добавить. |

Предупреждение выводится, если индекс дубликатов не охватил весь целевой почтовый ящик, что происходит при значении выше `PrefetchMaxMessages` или когда папку не удалось прочитать. В таком состоянии повторный запуск может добавить почту, которая уже присутствует в тех частях, которые не были проиндексированы.

## ⚠️ Notes and limits {#notes-and-limits}

- Восстановленная почта теперь несет свое **оригинальное время доставки** в качестве внутреннего IMAP-времени (internal date), взятого из цепочки `Received` сообщения с переходом к дате отправки. Ранее она несла время запуска архивации, что нарушало сортировку на стороне сервера по времени прибытия и любые правила, основанные на возрасте, в целевом ящике.
- Поскольку повторный запуск пропускает то, что уже присутствует, неверную внутреннюю дату нельзя исправить повторным запуском: сообщения будут распознаны и пропущены. Настройте это правильно перед рабочим запуском или удалите затронутые сообщения в целевом ящике и запустите снова.
- Microsoft 365 не поддерживается в качестве цели для offload.
- Обнаружение дубликатов может распознать только то, что оно может видеть в целевом почтовом ящике. Почта, попавшая в целевой ящик по другому пути, будет поймана только в том случае, если два критерия случайно совпадут с ней.

# 👥 ユーザー管理とメールボックス権限 {#user-management-and-mailbox-permissions}

[← Documentation Index に戻る](index.md)

## 📋 概要 {#overview}

このガイドでは、Mail Archiver アプリケーションにおける新しいユーザーアカウントの作成と、メールボックス権限の割り当てに関する詳細な手順を提供します。また、自身のパスワードの変更、および新規インストールされたインスタンスでの強制パスワード変更についても説明します。


## 🛠️ 前提条件 {#prerequisites}

- Mail Archiver アプリケーションへの管理者アクセス権
- システム内に設定済みの既存のメールアカウント


## 🧑‍💻 新規ユーザーアカウントの作成 {#creating-a-new-user-account}

1. 管理者権限を持つアカウントで Mail Archiver アプリケーションにログインします
2. メインメニューから "Users" セクションに移動します
3. "Create New User" ボタンをクリックします
4. 必要なユーザー情報を入力します：
   - **Username**: 新しいユーザーの一意のユーザー名を入力します
   - **Password**: ユーザーの安全なパスワードを入力します
   - **Email**: ユーザーのメールアドレス
   - **Admin**: ユーザーに管理者権限を付与する場合は、このボックスにチェックを入れます
   - **Self Manager**: ユーザーが自身のメールアカウントを管理（既存アカウントの編集、新規追加、およびアカウントの削除）できるようにする場合は、このボックスにチェックを入れます
   - **active**: ユーザーのログインを許可するには、これにチェックを入れる必要があります
5. "Create User" をクリックして、新しいユーザーアカウントを保存します

## 🔐 ユーザーへのメールボックス権限の割り当て {#assigning-mailbox-permissions-to-users}

1. ユーザーを作成した後、または既存のユーザーを編集する際に、メインメニューから "Users" セクションに移動します
2. メールアカウントを割り当てたいユーザーをリストから探し、そのユーザーの "Assign" ボタンをクリックします
3. "Assign Mail Accounts" ページに、利用可能なすべてのメールアカウントと、それらがユーザーに割り当てられているかを示すチェックボックスが表示されます
5. 新しいメールアカウントを割り当てるには、該当するアカウントのチェックボックスにチェックを入れます
6. ユーザーからメールアカウントを削除するには、チェックを外します
7. "Save Assignments" をクリックして変更を適用します

## 👤 ユーザーアカウントの権限 {#user-account-permissions}

### Admin Users（管理者ユーザー） {#admin-users}
管理者ユーザーはアプリケーションへのフルアクセス権を持ち、以下の操作が可能です：
- すべてのユーザーアカウントとその権限の管理
- システム内のすべてのメールアカウントへのアクセス
- すべてのアクセスログの閲覧
- すべての管理タスクの実行

### Self Manager Users（セルフマネージャーユーザー） {#self-manager-users}
セルフマネージャーユーザーは以下の操作が可能です：
- 自身のカウントへの新しいメールアカウントの追加
- 自身に割り当てられている既存のメールアカウントの編集
- 自身に割り当てられているメールアカウントの削除
- 割り当てられたアカウントからのメールへのアクセスと管理（削除を含む）
- 自身のアクセスログの閲覧

### Standard Users（標準ユーザー） {#standard-users}
標準ユーザーのアクセスは制限されており、以下の操作が可能です：
- 割り当てられたメールアカウントからのアーカイブ済みメールの閲覧
- 割り当てられたメールアカウント内での検索
- 割り当てられたアカウントからのメールのエクスポート
- 割り当てられたアカウントからのメールのリストア
- 割り当てられたアカウントからのメール添付ファイルへのアクセス

## 🔑 自身のパスワードの変更 {#changing-your-own-password}

ローカルパスワードを持つすべてのユーザーは、管理者なしでパスワードを変更できます：

1. 右上隅にある **username** をクリックして、ユーザーメニューを開きます。
2. **Change Password** を選択します。
3. **current password** と **new password** を2回入力し、送信します。

新しいパスワードは以下の要件を満たす必要があり、かつ**現在のパスワードとは異なる**ものである必要があります。

> ℹ️ **OIDC ユーザーはここでパスワードを変更することはできません。** このページには
> *"OIDC users cannot change their password. Password management is handled by
> your OIDC provider."* と表示されます。代わりに、使用している ID プロバイダーで
> パスワードを変更してください — [OIDC / SSO](OIDC_Implementation.md) を参照してください。

### パスワード要件 {#password-requirements}

- 最低 **10 文字**
- 最低 1 つの**大文字**
- 最低 1 つの**小文字**
- 最低 1 つの**数字**
- 最低 1 つの**特殊文字**

フォームには、入力中にこれらの要件がライブチェックリストとして表示されます。管理者がユーザーを作成したりパスワードをリセットしたりする場合も、同じルールが適用されます。

## ⚠️ 強制パスワード変更（初期セットアップ） {#forced-password-change-initial-setup}

新規インストールされたインスタンスは、設定（`Authentication__Username` / `Authentication__Password`）から提供される管理者資格情報で開始されます。そのデフォルトのパスワードがまだ使用されており、**かつメールアカウントがまだ存在しない限り**、最初のログイン時に変更が強制されます：

- 警告バナーに理由が表示されます：*"For security reasons, you must change your
  password before continuing. This is required because you are using the default
  system credentials on a newly set up system."*
- ページから離れることはできません：*"You must change your password before
  you can continue using the system."*
- 新しいパスワードは現在のものとは異なっていなければなりません。
- 保存後、フラグはクリアされ、ダッシュボードに移動します。

一度デフォルトのパスワードを変更すれば、強制変更は二度と表示されません。

## 🕒 サインイン状態の維持 — "Remember Me" チェックボックス {#staying-signed-in-the-remember-me-checkbox}

ログインフォームには **Remember Me** というラベルの付いたチェックボックスがあります（ドイツ語 UI では *angemeldet bleiben*）。これは、認証クッキーがセッションクッキーであるか、永続的なクッキーであるかを決定するという、たった一つの機能を持っています。

| | チェックなし | チェックあり |
|---|---|---|
| クッキーの有効期間 | `Authentication__SessionTimeoutMinutes` (デフォルト **60 分**) | **7 日間** |
| クッキーの種類 | セッションクッキー — ブラウザを閉じると破棄される | 永続クッキー — ディスクに保存される |
| ブラウザの再起動 | 再度ログインが必要 | サインイン状態が維持される |
| アイドルタイムアウト | すべてのリクエストごとに延長される (`SlidingExpiration`) | すべてのリクエストごとに延長される（最大 7 日間の制限まで） |
| サインアウト | セッションが直ちに終了する | セッションが直ちに終了する |

つまり、このチェックボックスは「このブラウザセッションの間、最大 60 分間のアイドル状態でサインイン」を、「ブラウザやマシンの再起動を含め、最大 7 日間サインイン」に変更するものです。

### チェックボックスが行わないこと {#things-the-checkbox-does-not-do}

- **パスワードやユーザー名を記憶することはありません。** 次回の訪問時にログインフォームが自動入力されることはなく、セッションクッキーのみが保持されます。
- **7 日間は固定の制限であり、設定変更はできません。** この値はコード内で固定されています (`Auth/Services/CookieAuthenticationService.cs`)。非永続的な有効期間のみが `Authentication__SessionTimeoutMinutes` に従います。
- **無操作タイマーではありません。** 7 日間はログイン時からカウントされます。たとえ 1 分前にアーカイブを使用していたとしても、期間が終了すれば新しいログインが必要になります。
- **ログアウト後も有効ではありません。** チェックボックスの状態に関わらず、*Logout* をクリックするとクッキーは削除されます。

### 2FA との相互作用 {#interaction-with-2fa}

2要素認証（2FA）が有効な場合、チェックボックスの状態は 2FA ステップの間保持され、2 番目の要素が成功した後にのみ適用されます。2FA のハンドオフはサーバー側のセッションで行われ、これ自体に **60 分間のアイドルタイムアウト** があります。その時間内にコードが入力されない場合、ログインは中断され、チェックボックスの選択も失われます。

### アプリケーションセッションとの相互作用 {#interaction-with-the-application-session}

Mail Archiver は、短期間の状態（2FA のハンドオフ、一括リストアの選択、最後の検索状態など）を保持するために、別の独立したサーバー側セッションを維持しています。このセッションには固定の **60 分間のアイドルタイムアウト** があり、永続的では*ありません*。有効な "Remember Me" クッキーを持つ状態でブラウザを再起動するとサインイン状態になりますが、そのセッション内で保持されていた保留中の操作は最初からやり直しになります。

### OIDC / SSO との相互作用 {#interaction-with-oidc-sso}

外部 ID プロバイダー経由でサインインするユーザーには、永続クッキーは発行されません。OIDC コールバックは常に `persistAuthentication: false` でセッションを開始します。これらのアカウントでは、チェックボックスは**効果がありません**。セッションの持続時間は ID プロバイダーのセッション設定によって決定されます。

> ⚠️ **セキュリティ上の注意。** 共用マシンや放置される可能性があるマシンでは、チェックボックスの**チェックを外したまま**にしてください。永続クッキーがあると、パスワードなしで最大 7 日間アーカイブにアクセスできてしまいます。これが許容できない環境では、`Authentication__SessionTimeoutMinutes` を短縮するか、ユーザーにチェックボックスを使用しないよう指示するか、プロバイダーが独自のセッションポリシーを強制する OIDC を使用してください。

## 🔒 セキュリティ上の考慮事項 {#security-considerations}

1. すべてのユーザーアカウントに強力なパスワードを使用する
2. インストール後、直ちにデフォルトの管理者パスワードを変更する
3. 管理者（Admin）権限は、必要とするユーザーにのみ割り当てる
4. セルフマネージャー（Self Manager）権限は、自身の管理を行う必要があるユーザーにのみ割り当てる
5. アクセス権が適切であることを確認するため、定期的にユーザー権限をレビューする
6. 不要になったユーザーのアクセス権は削除する
7. 最小権限の原則に従う — ユーザーが必要とするメールアカウントへのアクセスのみを割り当てる
